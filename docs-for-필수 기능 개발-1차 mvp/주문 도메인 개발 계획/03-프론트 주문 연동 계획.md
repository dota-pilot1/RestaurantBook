# 프론트 주문 연동 계획

## 현재 상태

파일:

```txt
restaurant-book-front/src/features/kiosk/KioskHome.tsx
```

현재 구현:

- 실제 고객 상품 API 조회
- 세트 탭과 일반 카테고리 탭 분리
- 카드 전체 클릭으로 장바구니 추가
- 장바구니 key는 `SALE_MENU:id`, `SALE_MENU_SET:id`
- `결제하기` 버튼은 아직 저장 API 미연동

다음 단계:

```txt
결제하기 클릭 -> POST /api/customer/orders -> 성공 안내 -> 장바구니 초기화
```

실제 결제 연동은 제외한다.

## 타입

```ts
import type { CustomerOrderType, SaleProductType } from "@/entities/customer-sale-product/model/types";

export type OrderStatus = "RECEIVED" | "COOKING" | "READY" | "COMPLETED" | "CANCELED";

export type CreateOrderItem = {
  type: SaleProductType;
  id: number;
  quantity: number;
};

export type CreateOrderBody = {
  orderType: CustomerOrderType;
  items: CreateOrderItem[];
};

export type OrderItemComponent = {
  name: string;
  quantity: number;
};

export type OrderItem = {
  id: number;
  type: SaleProductType;
  saleMenuId: number | null;
  saleMenuSetId: number | null;
  name: string;
  unitPrice: number;
  quantity: number;
  lineTotal: number;
  components: OrderItemComponent[];
};

export type Order = {
  id: number;
  orderNo: string;
  orderType: CustomerOrderType;
  status: OrderStatus;
  totalAmount: number;
  items: OrderItem[];
  createdAt: string;
};
```

## KioskHome 수정

수정 파일:

```txt
restaurant-book-front/src/features/kiosk/KioskHome.tsx
```

추가:

- `useMutation`으로 주문 생성
- 장바구니를 `CreateOrderBody.items`로 변환
- 중복 클릭 방지를 위해 mutation pending 중 결제 버튼 비활성화
- 성공 시 장바구니 초기화
- 실패 시 toast 또는 화면 메시지 표시

## 장바구니 변환

현재 장바구니:

```ts
Record<`${SaleProductType}:${number}`, CartItem>
```

주문 요청 변환:

```ts
const createOrderItems = cartItems.map((item) => ({
  type: item.type,
  id: item.id,
  quantity: item.quantity,
}));
```

요청:

```ts
{
  orderType: customerOrderType,
  items: createOrderItems,
}
```

## 성공 UX

MVP 권장:

```txt
주문이 접수되었습니다.
주문번호: 20260507173122-4821
```

구현 방식:

- `sonner` toast 사용
- 또는 우측 주문 패널 상단에 성공 상태 표시

MVP에서는 toast가 빠르다.

성공 후:

- 장바구니 비우기
- 현재 탭 유지
- 주문 유형 유지

## 실패 UX

서버에서 거절될 수 있는 상황:

- 상품이 품절됨
- 상품이 숨김 처리됨
- 매장/포장 주문 불가로 변경됨
- 장바구니 상품이 삭제됨

표시 문구:

```txt
주문을 접수하지 못했습니다. 메뉴 상태를 확인한 뒤 다시 시도해주세요.
```

구현:

- `toastError(e, "...")` 기존 helper 사용
- 실패 시 장바구니는 유지한다.

## 결제 버튼 문구

현재:

```txt
결제하기
```

MVP 주문 저장 단계에서는 실제 결제가 아니므로 문구를 바꾸는 것이 더 정확하다.

후보:

```txt
주문 접수하기
```

다만 화면 컨셉이 결제 진입이라면 버튼 문구는 `결제하기`로 유지하고 내부 동작만 주문 저장으로 시작해도 된다.

권장:

```txt
1차 주문 도메인 연동에서는 "주문 접수하기"
결제 연동 단계에서 "결제하기"로 변경
```

## 체크

- 장바구니가 비어 있으면 버튼 비활성화
- 주문 생성 중 버튼 비활성화
- 주문 생성 중 카드 추가/감소는 가능해도 되지만, 단순화를 위해 버튼만 막는다.
- 성공 시 장바구니 초기화
- 실패 시 장바구니 유지
- 서버 응답 총액과 프론트 총액이 다를 수 있음을 허용한다.
