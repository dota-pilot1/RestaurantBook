# 파일별 구현 체크리스트

## 1단계: 고객 상품 엔티티/API 추가

신규:

- `restaurant-book-front/src/entities/customer-sale-product/model/types.ts`
- `restaurant-book-front/src/entities/customer-sale-product/api/customerSaleProductApi.ts`

체크:

- `type: SALE_MENU | SALE_MENU_SET` discriminator 포함
- `components` 포함
- `orderType`, `section`, `categoryId` 필터 타입 정의

## 2단계: 고객 카테고리 접근 확인

수정 후보:

- `restaurant-book-server/src/main/java/com/cj/restaurantbook/config/SecurityConfig.java`
- `restaurant-book-server/src/main/java/com/cj/restaurantbook/sale_menu_category/presentation/SaleMenuCategoryController.java`

체크:

- 고객 페이지에서 카테고리 목록을 조회할 수 있어야 함
- 생성/수정/삭제 권한은 관리자/매니저 유지

## 3단계: KioskHome 하드코딩 제거

수정:

- `restaurant-book-front/src/features/kiosk/KioskHome.tsx`

제거:

- 하드코딩 `categories`
- 하드코딩 `menuItems`
- `Category = "set" | "rice" | "side" | "drink"`
- 색상 accent 기반 더미 이미지 영역

추가:

- `useQuery`로 카테고리 조회
- `useQuery`로 고객 상품 조회
- 주문 유형 변경 시 상품 재조회
- 탭 변경 시 상품 재조회

## 4단계: 장바구니 타입 변경

수정:

- `restaurant-book-front/src/features/kiosk/KioskHome.tsx`

기존:

```ts
Record<number, number>
```

변경:

```ts
Record<`${SaleProductType}:${number}`, CartItem>
```

체크:

- 단품과 세트 ID 충돌 없음
- 장바구니 표시 이름/가격은 담은 시점의 화면 데이터 사용
- 후속 주문 API에서는 `type`, `id`, `quantity`만 전송

## 5단계: 카드 UI 보완

수정:

- `MenuCard`

체크:

- 이미지가 있으면 `Image`로 표시
- 이미지가 없으면 안정적인 placeholder 표시
- 세트는 구성 요약 표시
- SOLD_OUT은 품절 배지와 추가 버튼 비활성화
- 가격/이름/설명이 모바일 너비에서 깨지지 않음

## 6단계: 상태 UI

추가:

- 로딩 상태
- 에러 상태
- 빈 목록 상태
- 전체 장바구니 비우기 후보

체크:

- API 실패 시 화면이 깨지지 않음
- 상품이 없는 카테고리도 정상 표시

## 7단계: 검증

명령:

```txt
restaurant-book-front: npm run build
restaurant-book-server: ./gradlew test
```

브라우저 확인:

```txt
http://localhost:4200/customer
```

시나리오:

- 세트 탭에 DB 세트가 보인다.
- 식사/국찌개/면분식/사이드/음료 탭에 DB 단품이 보인다.
- 매장/포장 전환 시 API 쿼리가 바뀐다.
- 세트와 단품을 함께 장바구니에 담아도 충돌하지 않는다.
- 품절 상품 추가가 막힌다.
