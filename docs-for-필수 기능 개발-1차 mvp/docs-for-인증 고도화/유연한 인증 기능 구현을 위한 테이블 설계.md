# 유연한 인증 기능 구현을 위한 테이블 설계

이 폴더는 이메일 로그인으로 먼저 시작하되, 이후 휴대폰 SMS/소셜 로그인으로 확장하기 쉬운 인증 구조를 정리한다.

문서는 총 4개로 유지한다. 이 정도가 읽기 흐름과 관리 난이도 사이에서 적당하다.

## 핵심 요약

```text
users
= 서비스 안의 실제 회원

auth_accounts
= 회원이 로그인할 수 있는 수단

auth_verifications
= 이메일/SMS 인증코드 같은 일회성 본인확인 절차
```

예약, 주문, 권한 같은 서비스 도메인은 `users.id`만 참조한다. 이메일, 전화번호, 구글 ID 같은 로그인 식별자는 `auth_accounts`에 둔다.
