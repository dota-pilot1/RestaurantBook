# 판매 메뉴 관리 구현 전체 로드맵

## 현재 상태

판매 메뉴 도메인은 아직 본격 구현 전이다.

현재 구현된 것은 아래 수준이다.

- `/sale-menus`
- `/sale-menu-categories`
- `/sale-menu-availability`
- 관리자 내비게이션 진입점
- 플레이스홀더 UI

아직 없는 것:

- `sale_menu` 백엔드 도메인
- `sale_menu_category` 백엔드 도메인
- `sale_menus` 테이블
- `sale_menu_categories` 테이블
- CRUD API
- 실제 프론트 엔티티/API
- 실제 판매 메뉴 관리 UI

따라서 다음 단계는 본격 CRUD 및 UI/UX 구현으로 들어가면 된다.

## 구현 목표

관리자가 고객 키오스크에 노출될 판매 메뉴를 관리할 수 있게 한다.

MVP에서 관리할 범위:

- 판매 메뉴 등록/수정/삭제
- 판매 메뉴 카테고리 등록/수정/삭제
- 가격 관리
- 대표 이미지 연결
- 판매 상태 관리
- 품절/숨김 상태 관리
- 매장/포장 노출 설정
- 정렬 순서 관리

MVP에서 제외할 범위:

- 옵션/추가 선택
- 세트 메뉴
- 가격 이력
- 시간대별 판매 가능 여부
- 재고 수량 기반 자동 품절
- 주문/결제 연동

## 권장 구현 순서

1. 백엔드 도메인과 테이블을 먼저 만든다.
2. 카테고리 CRUD API를 만든다.
3. 판매 메뉴 CRUD API를 만든다.
4. 프론트 엔티티와 API 모듈을 만든다.
5. `/sale-menus`를 실제 관리 화면으로 바꾼다.
6. `/sale-menu-categories`를 실제 카테고리 관리 화면으로 바꾼다.
7. `/sale-menu-availability`는 품절/노출 빠른 관리 화면으로 만든다.
8. 키오스크 화면은 최종적으로 `ACTIVE + visible + 주문유형 노출` 조건으로 판매 메뉴를 조회하게 연결한다.

## 네이밍 원칙

내비게이션 메뉴와 판매 메뉴를 절대 섞지 않는다.

```txt
헤더/관리자 이동 메뉴:
navigation_menu
navigation_menus
/api/navigation-menus

고객이 주문하는 판매 메뉴:
sale_menu
sale_menus
/api/sale-menus
```

## 완료 기준

- 관리자가 판매 메뉴를 생성할 수 있다.
- 관리자가 카테고리를 지정할 수 있다.
- 메뉴명, 가격, 설명, 이미지, 노출 상태를 수정할 수 있다.
- 품절/숨김/판매중 상태를 바꿀 수 있다.
- 매장/포장 노출 여부를 각각 바꿀 수 있다.
- 목록에서 검색, 필터, 상태 확인이 가능하다.
- 백엔드 컴파일과 프론트 빌드가 통과한다.
