# 폴링 시간 출력 하기

작성일: 2026-05-09

## 목적

WebSocket이 정상 동작하는지, 아니면 React Query의 `refetchInterval` 폴링에 의해 화면이 뒤늦게 갱신되는지 빠르게 구분하기 위한 임시 진단 UI다.

고객 화면에서 아래 값을 직접 보여주면 원인 분리가 쉽다.

- 마지막 WebSocket 이벤트 수신 시각
- 활성 주문 조회 폴링 완료 시각
- 취소 주문 조회 폴링 완료 시각
- 각 HTTP 조회 소요 시간
- 다음 폴링까지 남은 시간

## 적용 대상

고객 주문 화면:

```text
restaurant-book-front/src/features/kiosk/KioskHome.tsx
```

문제가 되었던 쿼리:

```ts
queryKey: ["customer-active-orders", tableName]
queryKey: ["customer-canceled-orders", tableName]
```

## 진단 상태 추가

`CancelNotice` 타입 아래에 임시 타입과 폴링 주기 상수를 추가한다.

```ts
type RealtimeDebugState = {
  lastWsAt: number | null;
  lastWsReason: string | null;
  lastWsOrderId: number | null;
  lastActivePollAt: number | null;
  lastActivePollMs: number | null;
  lastCanceledPollAt: number | null;
  lastCanceledPollMs: number | null;
};

const CUSTOMER_ORDER_REFETCH_INTERVAL_MS = 20000;
```

`KioskHome()` 내부 state 영역에 추가한다.

```ts
const [debugNow, setDebugNow] = useState(() => Date.now());
const [realtimeDebug, setRealtimeDebug] = useState<RealtimeDebugState>({
  lastWsAt: null,
  lastWsReason: null,
  lastWsOrderId: null,
  lastActivePollAt: null,
  lastActivePollMs: null,
  lastCanceledPollAt: null,
  lastCanceledPollMs: null,
});
```

1초마다 화면의 경과 시간을 갱신한다.

```ts
useEffect(() => {
  const timer = window.setInterval(() => setDebugNow(Date.now()), 1000);
  return () => window.clearInterval(timer);
}, []);
```

## WebSocket 수신 시각 기록

`useCustomerOrdersWebSocket()` 콜백 맨 위에 추가한다.

```ts
useCustomerOrdersWebSocket(tableName, tableName.trim().length > 0, (payload) => {
  setRealtimeDebug((current) => ({
    ...current,
    lastWsAt: Date.now(),
    lastWsReason: payload.reason ?? "UNKNOWN",
    lastWsOrderId: payload.orderId ?? null,
  }));

  const message = payload.cancelMessage?.trim();
  if (payload.reason !== "CANCELED" || !message) {
    return;
  }

  // 기존 취소 알림 처리 로직 유지
});
```

## 폴링 시각 기록

활성 주문 쿼리의 `queryFn`을 감싼다.

```ts
const {
  data: acceptedOrders = [],
  isLoading: activeOrdersLoading,
} = useQuery({
  queryKey: ["customer-active-orders", tableName],
  queryFn: async () => {
    const startedAt = Date.now();
    try {
      return await orderApi.getActiveCustomerOrders(tableName);
    } finally {
      const completedAt = Date.now();
      setRealtimeDebug((current) => ({
        ...current,
        lastActivePollAt: completedAt,
        lastActivePollMs: completedAt - startedAt,
      }));
    }
  },
  enabled: tableName.trim().length > 0,
  refetchInterval: CUSTOMER_ORDER_REFETCH_INTERVAL_MS,
});
```

취소 주문 쿼리도 같은 방식으로 감싼다.

```ts
const {
  data: canceledOrders = [],
} = useQuery({
  queryKey: ["customer-canceled-orders", tableName],
  queryFn: async () => {
    const startedAt = Date.now();
    try {
      return await orderApi.getCanceledCustomerOrders(tableName);
    } finally {
      const completedAt = Date.now();
      setRealtimeDebug((current) => ({
        ...current,
        lastCanceledPollAt: completedAt,
        lastCanceledPollMs: completedAt - startedAt,
      }));
    }
  },
  enabled: tableName.trim().length > 0,
  refetchInterval: CUSTOMER_ORDER_REFETCH_INTERVAL_MS,
});
```

## 화면에 표시

`주문 내역` 헤더 바로 아래에 패널을 추가한다.

```tsx
<RealtimeDebugPanel debug={realtimeDebug} now={debugNow} />
```

예시 위치:

```tsx
<div className="flex items-center justify-between border-b border-zinc-300 bg-zinc-50 px-4 py-3">
  ...
</div>
<RealtimeDebugPanel debug={realtimeDebug} now={debugNow} />
```

파일 하단에 임시 컴포넌트를 추가한다.

```tsx
function RealtimeDebugPanel({
  debug,
  now,
}: {
  debug: RealtimeDebugState;
  now: number;
}) {
  return (
    <div className="border-b border-zinc-200 bg-amber-50 px-4 py-2 text-[11px] font-semibold text-zinc-800">
      <div className="mb-1 flex items-center justify-between gap-2">
        <span className="text-amber-900">실시간 진단</span>
        <span className="rounded bg-white px-1.5 py-0.5 text-amber-900">
          폴링 주기 {Math.round(CUSTOMER_ORDER_REFETCH_INTERVAL_MS / 1000)}초
        </span>
      </div>
      <div className="grid gap-1">
        <DebugMetric
          label="WS"
          value={
            debug.lastWsAt
              ? `${formatDebugClock(debug.lastWsAt)} (${formatAgo(debug.lastWsAt, now)} 전) ${debug.lastWsReason ?? ""}${
                  debug.lastWsOrderId ? ` #${debug.lastWsOrderId}` : ""
                }`
              : "수신 없음"
          }
        />
        <DebugMetric
          label="활성 폴링"
          value={formatPollDebug(debug.lastActivePollAt, debug.lastActivePollMs, now)}
        />
        <DebugMetric
          label="취소 폴링"
          value={formatPollDebug(debug.lastCanceledPollAt, debug.lastCanceledPollMs, now)}
        />
      </div>
    </div>
  );
}

function DebugMetric({ label, value }: { label: string; value: string }) {
  return (
    <div className="flex min-w-0 items-center justify-between gap-2">
      <span className="shrink-0 text-zinc-500">{label}</span>
      <span className="min-w-0 truncate text-right tabular-nums">{value}</span>
    </div>
  );
}

function formatPollDebug(polledAt: number | null, durationMs: number | null, now: number) {
  if (!polledAt) {
    return "아직 없음";
  }
  const nextIn = Math.max(0, CUSTOMER_ORDER_REFETCH_INTERVAL_MS - (now - polledAt));
  return `${formatDebugClock(polledAt)} (${formatAgo(polledAt, now)} 전), ${durationMs ?? 0}ms, 다음 ${Math.ceil(nextIn / 1000)}초`;
}

function formatAgo(at: number, now: number) {
  return `${Math.max(0, Math.floor((now - at) / 1000))}초`;
}

function formatDebugClock(value: number) {
  return new Date(value).toLocaleTimeString("ko-KR", {
    hour: "2-digit",
    minute: "2-digit",
    second: "2-digit",
  });
}
```

## 판정 방법

### WebSocket 정상

주방에서 주문을 취소하자마자 `WS` 시간이 먼저 갱신된다.

```text
WS: 오후 08:31:12 (0초 전) CANCELED #33
취소 폴링: 오후 08:31:02 (10초 전), 12ms, 다음 10초
```

이 경우 고객 화면은 WebSocket으로 즉시 반응하고 있다.

### 폴링으로만 반응

주방에서 주문을 취소해도 `WS`가 계속 `수신 없음`이거나 오래된 시간이고, `취소 폴링` 시간이 바뀌는 순간 화면이 갱신된다.

```text
WS: 수신 없음
취소 폴링: 오후 08:31:20 (0초 전), 11ms, 다음 20초
```

이 경우 고객 화면이 WebSocket 이벤트를 받지 못하고 폴링 fallback으로만 반응하는 상태다.

## 확인 후 제거할 것

임시 진단이 끝나면 다음 코드를 제거한다.

- `RealtimeDebugState`
- `debugNow`, `realtimeDebug` state
- `setInterval`로 `debugNow` 갱신하는 effect
- WebSocket 콜백의 `setRealtimeDebug`
- 주문 쿼리의 시간 측정용 `async queryFn` wrapper
- `<RealtimeDebugPanel ... />`
- `RealtimeDebugPanel`, `DebugMetric`, `formatPollDebug`, `formatAgo`, `formatDebugClock`

폴링 fallback 주기 자체는 유지해도 된다. WebSocket이 정상일 때는 즉시 반응하고, 장애 시에만 느린 백업 경로로 동작한다.
