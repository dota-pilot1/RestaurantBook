# RestaurantBook 화면 크기별 뷰 관리

작성일: 2026-05-10

## 결론

현재 명시적으로 화면 크기 분기를 타는 핵심 파일은 고객 키오스크의 아래 3개다.

| 역할 | 파일 |
| --- | --- |
| 모바일 폭 감지 및 모바일 라우트 이동 | `restaurant-book-front/src/app/customer/page.tsx` |
| 모바일 키오스크 라우트 | `restaurant-book-front/src/app/customer/mobile/page.tsx` |
| 실제 키오스크 모바일/데스크톱 뷰 선택 및 렌더링 | `restaurant-book-front/src/features/kiosk/KioskHome.tsx` |

구조상 `모바일`은 JS 라우트 분기로 별도 화면을 사용하고, `태블릿/노트북`은 별도 라우트가 아니라 `KioskDesktopView` 내부 Tailwind breakpoint로 반응형 처리한다.

## 핵심 분기 파일

### 1. `/customer` 라우트

파일:

- `restaurant-book-front/src/app/customer/page.tsx`

현재 로직:

```ts
const mobileQuery = window.matchMedia("(max-width: 767px)");

if (mobileQuery.matches) {
  router.replace("/customer/mobile");
}
```

의미:

- 브라우저 viewport가 `767px 이하`이면 `/customer/mobile`로 이동한다.
- `768px 이상`이면 `/customer`에서 기본 `KioskHome`을 그대로 렌더링한다.
- 이 파일이 현재 가장 중요한 화면 크기 분기 진입점이다.

### 2. `/customer/mobile` 라우트

파일:

- `restaurant-book-front/src/app/customer/mobile/page.tsx`

현재 로직:

```tsx
return <KioskHome variant="mobile" />;
```

의미:

- 모바일 전용 라우트는 `KioskHome`에 `variant="mobile"`을 넘긴다.
- 이 값 때문에 실제 렌더링은 `KioskMobileView`로 갈린다.

### 3. 키오스크 뷰 선택

파일:

- `restaurant-book-front/src/features/kiosk/KioskHome.tsx`

현재 로직:

```tsx
export function KioskHome({ variant = "desktop" }: { variant?: "desktop" | "mobile" }) {
  const kiosk = useKioskOrder();

  if (variant === "mobile") {
    return <KioskMobileView kiosk={kiosk} />;
  }

  return <KioskDesktopView kiosk={kiosk} />;
}
```

의미:

- `variant="mobile"`이면 `KioskMobileView`
- 기본값이면 `KioskDesktopView`
- 주문/결제/직원 호출 등 상태 로직은 `useKioskOrder()`에서 공통으로 만들고, 화면만 모바일/데스크톱 컴포넌트로 나눈다.

## 화면 크기 기준

현재 명시 기준:

| 구간 | 처리 방식 | 기준 |
| --- | --- | --- |
| 모바일 | 별도 라우트 + `KioskMobileView` | `max-width: 767px` |
| 태블릿 세로/작은 태블릿 | `/customer` + `KioskDesktopView`의 작은 폭 레이아웃 | `768px 이상`, `lg` 미만 |
| 태블릿 가로/노트북 | `/customer` + `KioskDesktopView`의 `lg` 이상 레이아웃 | `1024px 이상` |
| 넓은 노트북/데스크톱 | `/customer` + `KioskDesktopView`의 `xl` 이상 카드 그리드 | `1280px 이상` |

Tailwind 기본 breakpoint 기준:

| Prefix | 최소 너비 |
| --- | --- |
| `sm` | `640px` |
| `md` | `768px` |
| `lg` | `1024px` |
| `xl` | `1280px` |
| `2xl` | `1536px` |

별도 `tailwind.config` 파일은 현재 확인되지 않았으므로 Tailwind 기본 breakpoint를 기준으로 본다.

## 데스크톱/태블릿 레이아웃 분기

파일:

- `restaurant-book-front/src/features/kiosk/KioskHome.tsx`

`KioskDesktopView`의 주요 반응형 클래스:

```tsx
<main className="... lg:h-[calc(100vh-3.5rem)] lg:overflow-hidden">
  <div className="... lg:h-full lg:grid-cols-[1fr_360px]">
```

의미:

- `lg` 미만: 세로 흐름, 페이지 전체 스크롤
- `lg` 이상: 메뉴 영역 + 주문 내역 사이드바 2단 구조, 내부 스크롤 중심

```tsx
<div className="flex-shrink-0 grid gap-2 sm:grid-cols-2 lg:grid-cols-4">
```

의미:

- 기본: 카테고리 버튼 1열
- `sm` 이상: 2열
- `lg` 이상: 4열

```tsx
<div id="kiosk-menu-list" className="grid gap-3 sm:grid-cols-2 xl:grid-cols-3">
```

의미:

- 기본: 메뉴 카드 1열
- `sm` 이상: 2열
- `xl` 이상: 3열

## 모바일 뷰 특징

파일:

- `restaurant-book-front/src/features/kiosk/KioskHome.tsx`

컴포넌트:

- `KioskMobileView`

특징:

- 상단 헤더와 카테고리 탭이 sticky로 고정된다.
- 메뉴는 그리드가 아니라 한 장씩 넘기는 카드 방식이다.
- 좌우 버튼과 touch swipe로 메뉴를 이동한다.
- 하단 주문/결제/직원 호출 영역은 fixed bottom bar로 고정된다.

관련 상태:

- `activeProductIndex`
- `slideDirection`
- `touchStartX`

## 현재 구조에서 주의할 점

1. `/customer`에서 모바일 폭이면 `/customer/mobile`로 replace만 한다.
   - 반대로 `/customer/mobile`에서 viewport가 커졌을 때 `/customer`로 되돌리는 로직은 현재 없다.

2. 모바일 기준은 `max-width: 767px`이고, Tailwind `md` 기준은 `768px`이다.
   - 둘이 맞물리도록 의도된 구조다.

3. 태블릿 전용 컴포넌트는 없다.
   - 태블릿은 `KioskDesktopView` 안에서 `sm`, `lg`, `xl` class로 처리된다.

4. 고객 키오스크 외의 일반 화면은 대부분 Tailwind class 기반 반응형이다.
   - 예: Header, AuthLayout, RoleHome, Admin 페이지 등
   - 별도 JS 분기보다 `hidden sm:inline`, `lg:grid-cols-*` 같은 class가 중심이다.

## 이후 개선 후보

- [ ] `/customer/mobile`에서 `768px 이상`이 되면 `/customer`로 되돌리는 resize 처리 추가 여부 결정
- [ ] 태블릿 전용 기준이 필요하면 `tablet` variant를 새로 만들지, `KioskDesktopView`의 `md/lg` class만 조정할지 결정
- [ ] 모바일 기준을 `767px`로 계속 유지할지, 실제 태블릿 운영 기기 해상도 기준으로 조정할지 결정
- [ ] 화면 크기 테스트 기준을 문서화
  - 모바일: 375px, 390px, 430px
  - 태블릿 세로: 768px, 820px
  - 태블릿 가로/노트북: 1024px, 1280px, 1440px

## 한 줄 요약
