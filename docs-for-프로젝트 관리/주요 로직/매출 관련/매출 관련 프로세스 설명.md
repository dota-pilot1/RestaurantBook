# 매출 관련 프로세스 설명

RestaurantBook의 매출 로직은 `orders`가 아니라 `payments`를 기준으로 한다. 직원이 결제 완료를 처리하는 순간 `payments` 테이블에 결제 기록이 저장되고, 매출 통계 페이지는 이 결제 기록을 기간별로 조회해서 화면에 표시한다.

## 매출 데이터가 생기는 시점

매출 데이터는 고객이 주문을 넣는 시점에는 생기지 않는다. 고객 주문은 후불 주문이므로, 주문 생성 시점에는 `orders`만 만들어진다.

매출 데이터는 직원 페이지에서 결제 완료를 누를 때 생성된다.

1. 주문이 `READY` 상태가 된다.
2. 직원이 결제 완료 모달을 연다.
3. 카드, 현금, 기타 중 하나를 선택한다.
4. 직원이 결제 완료 버튼을 누른다.
5. 서버가 주문 상태를 `COMPLETED`로 바꾼다.
6. 서버가 `payments` 테이블에 결제 기록을 저장한다.

저장되는 주요 값은 다음과 같다.

- `order_id`: 결제 대상 주문
- `amount`: 결제 당시 주문 총액
- `method`: `CARD`, `CASH`, `ETC`
- `status`: 최초 저장 시 `PAID`
- `paid_at`: 결제 완료 시각
- `handled_by`: 결제를 처리한 직원/관리자 id

`payments.order_id`에는 유니크 제약이 있어 한 주문에 결제 기록은 하나만 만들어진다. 같은 주문을 중복 결제 완료 처리하려고 하면 서버에서 차단한다.

## 결제수단

현재 결제수단은 세 가지다.

- `CARD`: 카드
- `CASH`: 현금
- `ETC`: 기타

후불 매장 운영 기준에서는 이 구분이 합리적이다. 고객은 테이블에서 주문하고, 직원이 실제 결제 시점에 결제수단을 확인한 뒤 기록한다. 이 값은 정산과 매출수단별 비율 계산에 바로 사용된다.

## 매출 조회 API

매출 페이지는 `/api/sales`를 호출한다.

조회 기준은 `paidAt`이다.

- 시작일 00:00:00 이상
- 종료일 다음날 00:00:00 미만
- 기준 시간대는 `Asia/Seoul`

예를 들어 2026-05-09 하루 조회라면 서버는 `2026-05-09 00:00:00 KST`부터 `2026-05-10 00:00:00 KST` 직전까지의 결제 기록을 찾는다.

매출 조회 응답에는 다음 정보가 포함된다.

- 조회 시작일
- 조회 종료일
- 순매출
- 결제 건수
- 환불 금액
- 환불 건수
- 결제수단별 매출
- 최근 결제 목록
- 최근 환불 목록

최근 결제 목록과 최근 환불 목록은 각각 최대 50건까지만 내려준다.

## 매출 페이지 표시

프론트 매출 페이지는 `/sales`다.

기본 조회 기간은 오늘이며, 다음 프리셋을 제공한다.

- 오늘
- 최근 7일
- 이번 달
- 직접 선택

현재 화면에서 바로 표시하는 주요 지표는 다음과 같다.

- 순매출
- 결제 건수
- 환불
- 최근 결제 목록
- 최근 환불 목록
- 결제수단별 매출

결제수단별 매출은 카드, 현금, 기타 각각의 금액과 건수, 전체 결제 대비 비율을 보여준다.

## 환불 처리와 매출 반영

환불은 직원 페이지에서 결제 완료 주문에 대해 처리한다.

환불이 실행되면 다음 일이 일어난다.

1. 주문 상태가 `COMPLETED -> CANCELED`로 바뀐다.
2. 연결된 결제 기록의 상태가 `PAID -> REFUNDED`로 바뀐다.
3. `refundedAt`, `refundedBy`가 저장된다.
4. 매출 쿼리가 갱신된다.

현재 매출 조회는 `PAID` 상태의 결제만 순매출과 결제수단별 매출에 포함한다. 환불된 결제는 `REFUNDED` 상태가 되므로 순매출 목록에서는 빠지고, 환불 목록에는 `refundedAt` 기준으로 잡힌다.

따라서 현재 구현의 핵심 매출 지표는 “조회 기간 내 실제 남은 매출”인 순매출이다. 환불된 결제를 총매출에 포함해 보여주는 방식도 가능하지만, 매장 운영 화면에서는 환불 제외 후 남은 금액을 바로 보는 편이 더 직관적이다.

별도의 총 결제액이 필요해지면 환불된 결제도 최초 결제일 기준으로 포함한 지표를 추가하면 된다. 현재 MVP에서는 총매출을 별도 표시하지 않고, 순매출과 환불액을 나눠 보여주는 기준으로 간다.

## 직원 페이지와 매출 페이지의 역할 분리

직원 페이지는 주문 처리와 결제 완료가 목적이다. 따라서 결제 목록이나 상세 통계를 많이 넣으면 주문 보드의 목적이 흐려질 수 있다.

권장 역할 분리는 다음과 같다.

- 직원 페이지: 결제 대기 주문, 결제 완료 처리, 환불 처리, 필요 시 오늘 결제 요약 정도
- 매출 페이지: 결제 목록, 환불 목록, 결제수단별 매출, 기간별 집계

이 구조가 유지되면 직원은 운영 흐름에 집중하고, 관리자/매니저는 매출과 정산 흐름을 확인할 수 있다.

## 현재 가장 중요한 매출 원칙

매출 로직에서 가장 중요한 기준은 다음 두 가지다.

- 주문이 아니라 `Payment`가 매출의 원천 데이터다.
- 결제 완료 시점의 `paidAt`, 결제수단 `method`, 결제금액 `amount`가 통계의 기준이다.

즉 주문이 `COMPLETED`라고 해서 매출을 계산하는 것이 아니라, 해당 주문에 연결된 `payments` 레코드를 조회해서 매출을 계산한다.
