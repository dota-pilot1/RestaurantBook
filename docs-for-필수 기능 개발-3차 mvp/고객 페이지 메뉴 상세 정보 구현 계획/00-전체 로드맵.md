# 고객 페이지 메뉴 상세 정보 구현 계획

## 목표

고객 키오스크 메뉴 카드에서 각 메뉴의 상세 정보와 영양 정보를 확인할 수 있게 한다.

- 카드 우상단에 상세 정보 `i` 버튼을 배치한다.
- `i` 버튼 클릭 시 메뉴 선택 토글이 발생하지 않고 상세 다이얼로그만 열린다.
- 메뉴가 선택되면 기존 체크 표시를 우상단에 유지하고 `i` 버튼은 숨긴다.
- 다이얼로그는 왼쪽에 메뉴 상세 정보, 오른쪽에 영양 정보를 배치한다.
- 모바일에서는 상세 정보와 영양 정보를 세로로 쌓는다.

## UI 결정

1. 카드 선택 전
   - 이미지 우상단: `Info` 아이콘 버튼
   - 품절 배지가 필요하면 이미지 좌상단으로 이동
   - 카드 전체 클릭은 기존처럼 담기 동작
   - `Info` 버튼 클릭은 `event.stopPropagation()` 처리

2. 카드 선택 후
   - 이미지/카드 우상단: 기존 체크 표시만 노출
   - `Info` 버튼은 숨김
   - 수량 조절 영역은 기존 유지

3. 다이얼로그
   - 제목: 메뉴명
   - 상단 보조 정보: 가격, 카테고리/세트, 품절 상태
   - 왼쪽: 이미지, 설명, 구성, 원재료/알레르기 정보
   - 오른쪽: 열량, 탄수화물, 단백질, 지방, 나트륨 등 영양 정보

## 단계

1. 백엔드 데이터 모델 확장
   - 판매 메뉴와 세트 메뉴에 상세/영양 정보 필드 추가
   - 요청/응답 DTO 반영
   - 고객 상품 조회 응답에 상세/영양 정보 포함

2. 관리자 입력 화면 확장
   - 판매 메뉴 등록/수정 폼에 상세/영양 정보 입력 필드 추가
   - 세트 메뉴 등록/수정 폼에도 동일 필드 추가

3. 프론트 고객 타입/API 반영
   - `CustomerSaleProduct` 타입에 상세/영양 정보 추가
   - 기존 목록 API 응답 구조와 맞춤

4. 고객 카드/다이얼로그 구현
   - `MenuCard`에 `Info` 버튼과 `onOpenDetail` prop 추가
   - `useKioskOrder`에 선택된 상세 상품 상태 추가
   - `KioskDialogs`에 메뉴 상세 다이얼로그 추가
   - 데스크톱/모바일 뷰에서 `onOpenDetail` 연결

5. 검증
   - 선택 전/후 아이콘 겹침 확인
   - 카드 클릭과 정보 버튼 클릭 이벤트 분리 확인
   - 모바일 다이얼로그 레이아웃 확인
   - 영양 정보가 없는 메뉴의 빈 상태 확인

## 비범위

- 영양 정보를 자동 계산하지 않는다.
- 세트 메뉴 영양 정보를 구성 단품에서 자동 합산하지 않는다.
- 상세 정보 조회용 별도 API를 만들지 않고, 우선 기존 고객 상품 목록 응답에 포함한다.
