# 02. 프론트 데이터 및 관리자 입력 계획

## 타입 확장

### `restaurant-book-front/src/entities/customer-sale-product/model/types.ts`

추가 타입:

```ts
export type CustomerSaleProductDetail = {
  description: string | null;
  ingredients: string | null;
  allergens: string | null;
};

export type CustomerSaleProductNutrition = {
  caloriesKcal: number | null;
  carbohydrateG: number | null;
  proteinG: number | null;
  fatG: number | null;
  sodiumMg: number | null;
};
```

`CustomerSaleProduct`에 추가:

```ts
detail: CustomerSaleProductDetail | null;
nutrition: CustomerSaleProductNutrition | null;
```

주의:

- 기존 카드 설명은 `product.description`을 계속 사용한다.
- 다이얼로그의 상세 설명은 `product.detail?.description`을 우선 사용하고, 없으면 `product.description`으로 fallback한다.

## 관리자 입력 화면

### `restaurant-book-front/src/features/sale-menu-management/SaleMenuFormDialog.tsx`

작업:

1. zod schema에 신규 필드 추가
   - 텍스트: `z.string().max(...).optional()`
   - 숫자: `z.number().min(0).nullable().optional()` 또는 빈 문자열 처리가 쉬운 input 변환 사용

2. `defaultValues()`에 신규 필드 추가

3. 수정 모드 defaultValues에 `menu`의 신규 필드 매핑

4. 저장 body에 신규 필드 추가
   - 텍스트는 trim 후 빈 문자열이면 null
   - 숫자는 빈 값이면 null

5. UI 배치
   - 기존 `설명` 아래에 `상세 설명`, `원재료`, `알레르기 정보`
   - 별도 섹션 `영양 정보`를 만들고 숫자 input 5개 배치

권장 UI:

- 상세 설명: textarea rows 3
- 원재료: textarea rows 3
- 알레르기 정보: input 또는 textarea rows 2
- 영양 정보: `md:grid-cols-5` 또는 `md:grid-cols-3`

### `restaurant-book-front/src/features/sale-menu-set-management/SaleMenuSetFormDialog.tsx`

단품 메뉴 폼과 동일하게 반영한다.

세트 메뉴 주의:

- 구성 품목 아래보다 대표 정보 영역 아래에 상세/영양 입력을 둔다.
- 세트 영양 정보는 직접 입력한다는 전제로 안내 문구를 짧게 둔다.

## 프론트 데이터 완료 기준

- 단품 메뉴 생성/수정 화면에서 상세/영양 정보를 저장할 수 있다.
- 세트 메뉴 생성/수정 화면에서 상세/영양 정보를 저장할 수 있다.
- 고객 메뉴 API 타입이 백엔드 응답과 일치한다.
- 상세/영양 정보가 null이어도 고객 화면이 깨지지 않는다.
