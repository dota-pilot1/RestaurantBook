# 02. 고객 키오스크 전체 보기 후속 계획

## 결론

고객 키오스크에는 `전체 보기`를 추가할 수 있다. 다만 기본 선택으로 두지 않고, 카테고리 버튼의 마지막 보조 옵션으로 둔다.

`전체 보기`는 모든 메뉴를 한 줄 목록으로 섞지 않는다. 관리자가 조정한 카테고리 순서를 기준으로 섹션을 나누어 보여준다.

상세 구현 계획은 별도 문서에서 관리한다.

- [고객 페이지 전체 조회 (순서 고려)](../고객%20페이지%20전체%20조회%20(순서%20고려)/README.md)

## 추천 UX

카테고리 버튼:

```text
[식사] [국/찌개] [면/분식] [사이드] [음료] [세트] [전체 보기]
```

초기 진입:

- 첫 번째 실제 카테고리 선택
- 예: `식사`

`전체 보기` 선택 시:

```text
식사
- 육회 비빔밥
- 제육 덮밥

국/찌개
- 김치 찌개
- 된장 찌개

면/분식
- 잔치 국수
- 떡볶이
```

## 왜 전체 flat list는 피하는가

전체 메뉴를 하나의 flat list로 섞으면 카테고리 순서 조절의 의미가 약해진다.

예를 들어 관리자가 `식사 → 국/찌개 → 면/분식 → 사이드 → 음료` 순서로 정리했는데, `전체 보기`에서 메뉴 `displayOrder`만 보고 섞어버리면 고객은 화면 흐름을 예측하기 어렵다.

따라서 `전체 보기`에서도 카테고리 순서를 상위 기준으로 유지한다.

## 구현 방향

후속 작업 파일 후보:

- `restaurant-book-front/src/features/customer-menu/...`
- `restaurant-book-front/src/entities/customer-sale-product/api/customerSaleProductApi.ts`
- `restaurant-book-front/src/entities/customer-sale-product/model/types.ts`
- `restaurant-book-server/src/main/java/com/cj/restaurantbook/customer_menu/application/CustomerSaleProductService.java`
- `restaurant-book-server/src/main/java/com/cj/restaurantbook/customer_menu/presentation/CustomerSaleProductController.java`

정확한 파일은 후속 구현 시 현재 고객 키오스크 컴포넌트 구조를 다시 확인한다.

## 데이터 요구사항

`전체 보기`를 프론트에서 섹션 렌더링하려면 응답 데이터에 다음 정보가 안정적으로 있어야 한다.

- 메뉴의 카테고리 id
- 메뉴의 카테고리 name
- 카테고리 순서 또는 이미 카테고리 순서가 반영된 메뉴 목록

현재 백엔드 판매 메뉴 조회는 카테고리 순서를 반영한다. 고객 메뉴 API도 같은 정렬 기준을 유지하는지 확인해야 한다.

## 구현 옵션

### Option A. 프론트에서 그룹핑

API가 전체 메뉴를 카테고리 순서대로 내려준다.

프론트는 응답 배열을 순회하면서 카테고리별로 그룹핑한다.

장점:

- 백엔드 변경이 작다.
- 현재 정렬 쿼리를 그대로 활용할 수 있다.

단점:

- 응답이 카테고리 정보를 충분히 포함해야 한다.
- 세트 메뉴 등 다른 상품 타입이 섞이면 그룹핑 규칙을 더 명확히 해야 한다.

### Option B. 백엔드에서 섹션 구조로 응답

API가 다음 형태로 내려준다.

```json
[
  {
    "categoryId": 1,
    "categoryName": "식사",
    "items": []
  }
]
```

장점:

- 고객 화면 렌더링이 명확하다.
- 카테고리 섹션 순서가 API 계약으로 고정된다.

단점:

- API 변경 범위가 커진다.

MVP 후속은 Option A를 먼저 검토한다.

## 검증

- 고객 키오스크 기본 진입 시 첫 실제 카테고리가 선택된다.
- `전체 보기` 버튼이 카테고리 마지막에 표시된다.
- `전체 보기`에서 카테고리 섹션 순서가 관리자 DnD 순서와 일치한다.
- 각 섹션 내부 메뉴 순서가 기존 메뉴 정렬 기준과 일치한다.
- 카테고리가 숨김이면 `전체 보기` 섹션에도 노출되지 않는다.
- 품절/숨김/주문 유형 필터가 기존과 동일하게 적용된다.
- 모바일/키오스크 폭에서 섹션 제목과 카드가 겹치지 않는다.

## 후속으로 남기는 이유

`전체 보기`는 고객 주문 경험에 직접 영향을 준다. 먼저 관리자 카테고리 순서 조절을 안정화한 뒤, 그 순서를 고객 화면에서 소비하는 방식으로 구현하는 편이 안전하다.

작업 순서:

1. 관리자 카테고리 순서 조절 구현
2. 판매 메뉴 목록 정렬 회귀 확인
3. 고객 키오스크 현재 정렬 기준 확인
4. `전체 보기`를 카테고리 섹션 방식으로 추가
