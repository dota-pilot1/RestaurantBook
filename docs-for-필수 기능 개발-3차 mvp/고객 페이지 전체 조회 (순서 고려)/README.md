# 고객 페이지 전체 조회 (순서 고려) 구현 계획

작성일: 2026-05-10

## 결론

고객 키오스크에는 `전체 보기`를 추가한다.

다만 `전체 보기`는 기본 선택이 아니라 카테고리 버튼의 마지막 보조 옵션으로 둔다. 기본 진입은 첫 번째 실제 카테고리다.

`전체 보기`를 선택했을 때는 모든 메뉴를 하나의 flat list로 섞지 않고, **카테고리 섹션 단위**로 묶어 보여준다. 섹션 순서는 관리자가 조정한 카테고리 `displayOrder`를 따른다.

## 선행 작업

먼저 다음 작업이 완료되어야 한다.

- [판매 메뉴 카테고리별 순서 바꾸기 구현 계획](../판매%20메뉴%20카테고리별%20순서%20바꾸기%20구현%20계획/README.md)

선행 작업 완료 기준:

- 관리자 판매 메뉴 화면에서 카테고리 순서를 DnD로 변경할 수 있다.
- 변경된 카테고리 순서가 판매 메뉴 조회 정렬에 반영된다.
- 고객 메뉴 API도 카테고리 순서를 소비할 준비가 되어 있다.

## UX 정책

카테고리 버튼:

```text
[식사] [국/찌개] [면/분식] [사이드] [음료] [세트] [전체 보기]
```

초기 진입:

- 첫 번째 실제 카테고리 선택
- 예: `식사`

`전체 보기` 선택 시:

```text
식사
- 육회 비빔밥
- 제육 덮밥

국/찌개
- 김치 찌개
- 된장 찌개

면/분식
- 잔치 국수
- 떡볶이
```

## 왜 전체 flat list는 제외하는가

카테고리 순서를 운영자가 조절할 수 있게 만들었는데, `전체 보기`에서 모든 메뉴를 섞어 보여주면 그 순서의 의미가 약해진다.

고객 입장에서도 카테고리별 맥락이 유지되는 편이 찾기 쉽다. 특히 식사, 국/찌개, 면/분식, 음료가 섞이면 키오스크에서 빠르게 고르기 어렵다.

따라서 `전체 보기`는 “전체 메뉴를 한 화면에서 볼 수 있게 하는 기능”이지, “카테고리 구분을 없애는 기능”이 아니다.

## 완료 기준

- 고객 키오스크 카테고리 버튼 마지막에 `전체 보기`가 있다.
- 기본 선택은 `전체 보기`가 아니라 첫 번째 실제 카테고리다.
- `전체 보기`는 카테고리 섹션 단위로 렌더링된다.
- 섹션 순서는 관리자 카테고리 DnD 순서와 일치한다.
- 각 섹션 내부 메뉴 순서는 기존 메뉴 정렬 기준과 일치한다.
- 기존 주문 담기, 주문 내역, 결제, 직원 호출 흐름에 회귀가 없다.
