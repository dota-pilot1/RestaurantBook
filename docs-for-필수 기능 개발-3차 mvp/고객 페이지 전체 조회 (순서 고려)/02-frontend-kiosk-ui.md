# 02. 프론트 고객 키오스크 UI 계획

## 목표

고객이 카테고리별로 메뉴를 고를 수 있는 현재 흐름을 유지하면서, 필요할 때 모든 메뉴를 한 화면에서 훑어볼 수 있게 한다.

`전체 보기`는 고객 편의를 위한 보조 기능이다. 기본 탐색 방식은 여전히 카테고리별 탐색이다.

## UI 정책

카테고리 버튼:

- 실제 카테고리 버튼을 먼저 표시한다.
- 마지막에 `전체 보기` 버튼을 추가한다.
- `전체 보기`는 카테고리와 같은 스타일의 토글 버튼으로 표시한다.

초기 선택:

- 첫 번째 visible 카테고리.
- visible 카테고리가 없다면 빈 상태를 표시한다.
- `전체 보기`를 초기 선택으로 두지 않는다.

전체 보기 렌더링:

- 카테고리 섹션 제목을 표시한다.
- 섹션 아래에 해당 카테고리 메뉴 카드를 표시한다.
- 카테고리 섹션 순서는 관리자 카테고리 순서와 일치한다.
- 섹션 내부 메뉴 순서는 기존 메뉴 순서와 일치한다.

## 레이아웃 고려

현재 고객 화면은 좌측 메뉴 영역과 우측 주문 내역 영역으로 나뉜다.

`전체 보기`에서는 메뉴 카드 수가 많아지므로 다음을 지킨다.

- 섹션 제목은 카드 grid 밖에 둔다.
- 섹션 간 간격을 충분히 둔다.
- sticky category tab은 현 구조가 허용할 때만 검토한다.
- 우측 주문 내역 영역을 침범하지 않는다.
- 모바일/좁은 폭에서 섹션 제목과 카드가 겹치지 않는다.

## 빈 상태

전체 보기에서 표시할 메뉴가 없으면:

```text
표시할 메뉴가 없습니다.
```

특정 카테고리에 메뉴가 없으면:

- 해당 섹션은 숨긴다.
- 모든 섹션이 비면 전체 빈 상태만 표시한다.

## 주문 유형 필터

매장/포장 선택 상태는 전체 보기에도 동일하게 적용한다.

예:

- 매장 주문 선택 시 `availableDineIn = true` 메뉴만 표시.
- 포장 주문 선택 시 `availableTakeout = true` 메뉴만 표시.

## 세트 메뉴 처리

현재 고객 화면에서 세트 메뉴가 별도 카테고리처럼 보인다면 `세트` 섹션으로 유지한다.

원칙:

- 세트가 기존 카테고리 응답에 포함된다면 해당 카테고리에 표시한다.
- 세트가 별도 상품 타입이면 `세트` 섹션으로 마지막 또는 서버 응답 순서에 맞춰 표시한다.
- 이 정책은 데이터/API 확인 단계에서 확정한다.

## 검증

- [ ] 첫 진입 시 첫 번째 실제 카테고리가 선택된다.
- [ ] `전체 보기`가 카테고리 버튼 마지막에 있다.
- [ ] `전체 보기` 클릭 시 섹션 제목과 메뉴 카드가 표시된다.
- [ ] 섹션 순서가 관리자 카테고리 순서와 일치한다.
- [ ] 매장/포장 전환 시 전체 보기 메뉴도 같이 갱신된다.
- [ ] 메뉴 추가 버튼 동작이 기존과 동일하다.
- [ ] 우측 주문 내역이 기존과 동일하게 갱신된다.
- [ ] 주문 접수/결제/직원 호출 버튼에 회귀가 없다.
