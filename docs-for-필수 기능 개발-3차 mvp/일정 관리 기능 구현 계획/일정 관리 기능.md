## 결론

BeautyBook의 관리자 일정 관리는 RestaurantBook의 `관리 > 운영 관리` 하위에 **일정 관리**로 추가하는 것이 적절하다.

RestaurantBook은 예약 중심 앱이 아니라 키오스크/주문/주방/매출 중심 앱이므로, 일정의 의미를 다음처럼 바꾼다.

- BeautyBook: 매장 공지, 휴무, 이벤트, 메모
- RestaurantBook: 운영 공지, 휴무/임시휴업, 프로모션/단체예약, 운영 메모

기능 구조는 최대한 BeautyBook을 그대로 가져간다.

- 좌측 월간 캘린더
- 우측 이 달 일정 목록
- 캘린더 날짜 클릭 시 우측 목록 필터
- `+ 새 일정` 버튼
- 행 클릭 시 수정/삭제 모달
- 월 범위 조회 API + 생성/수정/삭제 API
- Tanstack Query invalidate로 저장 직후 화면 갱신

## RestaurantBook에 맞게 바꿀 부분

| 구분 | BeautyBook | RestaurantBook 적용 |
|------|------------|---------------------|
| 메뉴 위치 | 관리자 사이드바 `관리자 일정 관리` | 헤더 메가메뉴 `관리 > 운영 관리 > 일정 관리` |
| 페이지 경로 | `/admin/calendar` | 동일하게 `/admin/calendar` |
| API 경로 | `/api/admin/calendar/entries` | 동일하게 `/api/admin/calendar/entries` |
| 패키지 | `com.cj.beautybook.admin_calendar` | `com.cj.restaurantbook.admin_calendar` |
| 테이블 | `admin_calendar_entry` | RestaurantBook 컨벤션에 맞춰 `admin_calendar_entries` 권장 |
| 일정 타입 | `NOTICE/HOLIDAY/EVENT/MEMO` | enum은 동일하게 유지, 라벨과 placeholder만 식당 운영형으로 변경 |
| 권한 | `ROLE_ADMIN` | MVP는 `ROLE_ADMIN`. 매니저 공개는 후속 결정 |
| UI 톤 | BeautyBook teal 계열 | RestaurantBook의 기존 관리자 화면 색/카드/버튼 톤 유지 |

## MVP 범위

이번 3차 MVP에서는 **날짜 단위 비정형 운영 일정**만 다룬다.

포함:
- 월별 일정 조회
- 일정 등록/수정/삭제
- 날짜/타입/시간 텍스트/제목/내용
- 작성자 ID 저장
- 운영 관리 메뉴 추가
- 관리자 권한 가드

제외:
- 반복 일정
- 알림톡/웹푸시 알림
- 영업시간 자동 변경
- 주문/매출/주방 보드에 일정 자동 반영
- 단체예약을 주문/테이블 점유와 연결
- 매니저 권한 노출 정책 변경

## 우선 구현 순서

1. 백엔드 도메인과 테이블을 만든다.
2. 월 범위 조회/등록/수정/삭제 API를 붙인다.
3. 프론트 entity API와 query hook을 만든다.
4. BeautyBook 캘린더 화면을 RestaurantBook 스타일로 옮긴다.
5. 운영 관리 메뉴와 관리자 대시보드 진입점을 추가한다.
6. 권한/빈 상태/모바일/배포 전 체크를 끝낸다.

자세한 구현 순서는 [06-step-by-step.md](./06-step-by-step.md)를 기준으로 진행한다.
