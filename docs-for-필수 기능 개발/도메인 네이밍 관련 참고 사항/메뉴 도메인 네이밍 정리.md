# 메뉴 도메인 네이밍 정리

## 결론

음식점 서비스에서 `menu`는 기본적으로 고객이 주문하는 판매 상품으로 읽힌다.

따라서 헤더, 관리자 이동, 화면 라우팅에 쓰는 기존 `menu` 도메인은 `navigation_menu`로 분리한다.

## 네이밍 기준

| 의미 | 백엔드 패키지 | 테이블 | API | 프론트 엔티티 |
| --- | --- | --- | --- | --- |
| 헤더/관리자 내비게이션 메뉴 | `navigation_menu` | `navigation_menus` | `/api/navigation-menus` | `navigation-menu` |
| 고객이 주문하는 판매 메뉴 | `sale_menu` | `sale_menus` | `/api/sale-menus` | `sale-menu` |

## 현재 적용한 변경

- 기존 `com.cj.restaurantbook.menu` 패키지를 `com.cj.restaurantbook.navigation_menu`로 변경한다.
- 기존 `menus` 테이블명은 `navigation_menus`로 변경한다.
- 기존 `/api/menus`는 `/api/navigation-menus`로 변경한다.
- 프론트 `src/entities/menu`는 `src/entities/navigation-menu`로 변경한다.
- 프론트 `src/features/menu-management`는 `src/features/navigation-menu-management`로 변경한다.
- 헤더 메뉴 관리 화면 경로는 `/navigation-menus`를 사용한다.

## 앞으로의 판매 메뉴 도메인

판매 메뉴는 내비게이션 메뉴와 완전히 다른 도메인이다.

판매 메뉴 MVP는 아래 이름을 사용한다.

```txt
sale_menu
sale_menus
/api/sale-menus
src/entities/sale-menu
```

판매 메뉴 카테고리는 아래 이름을 사용한다.

```txt
sale_menu_category
sale_menu_categories
/api/sale-menu-categories
src/entities/sale-menu-category
```

## 주의점

- `Menu`, `MenuService`, `MenuRepository`, `/api/menus` 같은 단독 `menu` 이름은 신규 코드에서 쓰지 않는다.
- 화면에 노출되는 문구도 가능하면 `메뉴` 단독 표현보다 `내비게이션 메뉴` 또는 `판매 메뉴`로 구체화한다.
- 주문, 키오스크, 가격, 품절, 이미지, 옵션은 모두 `sale_menu` 쪽 책임이다.
- 헤더 노출, 라우팅, 관리자 드롭다운 구성은 모두 `navigation_menu` 쪽 책임이다.
