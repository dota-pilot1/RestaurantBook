# 고객 페이지 실제 메뉴 출력 전체 로드맵

## 결론

다음 단계는 고객 키오스크 화면의 하드코딩 메뉴를 실제 DB/API 데이터로 교체하는 것이다.

현재 고객 페이지는 `restaurant-book-front/src/features/kiosk/KioskHome.tsx` 안에 `categories`, `menuItems`가 고정되어 있다. 이제 관리자에서 등록한 단품 판매 메뉴와 세트 메뉴를 고객 화면에 그대로 출력해야 한다.

핵심 원칙:

```txt
세트 탭 = sale_menu_sets 조회 섹션
일반 카테고리 탭 = sale_menu_categories + sale_menus 조회
장바구니 키 = type + id
주문 item type = SALE_MENU | SALE_MENU_SET
```

## 사용할 API

이미 백엔드에 추가된 고객용 union API를 우선 사용한다.

```txt
GET /api/customer/sale-products
```

쿼리:

```txt
orderType=DINE_IN|TAKEOUT
section=ALL|SET|MENU
categoryId={sale_menu_categories.id}
```

응답의 `type`으로 단품과 세트를 구분한다.

```txt
SALE_MENU
SALE_MENU_SET
```

## MVP 범위

포함:

- 고객 화면 탭을 실제 카테고리 데이터로 구성
- `세트` 탭은 카테고리가 아니라 고정 섹션으로 구성
- 세트 메뉴와 단품 메뉴를 API에서 조회해 카드 출력
- 품절 상품은 보이지만 장바구니 추가 불가
- 숨김 상품은 API에서 내려오지 않음
- 매장/포장 선택에 따라 주문 가능한 상품만 노출
- 장바구니를 `type + id` 기준으로 관리
- 세트 카드에 구성 품목 요약 표시

제외:

- 실제 주문 저장 API 연동
- 결제 연동
- 선택형 세트 구성
- 이미지 자동 생성/보정

## 구현 순서

1. 고객 상품 프론트 엔티티/API를 추가한다.
2. 고객 화면 탭을 `세트` + 실제 판매 메뉴 카테고리로 바꾼다.
3. 탭/주문 유형 변경 시 `/api/customer/sale-products`를 조회한다.
4. 메뉴 카드 타입을 `SALE_MENU | SALE_MENU_SET` 공통 타입으로 바꾼다.
5. 장바구니 키를 `type:id`로 바꾼다.
6. 품절/빈 상태/로딩/에러 상태를 표시한다.
7. 고객 화면을 빌드 및 브라우저에서 검증한다.

## 완료 기준

- 관리자에서 등록한 세트 메뉴가 고객 화면 `세트` 탭에 표시된다.
- 관리자에서 등록한 단품 메뉴가 해당 카테고리 탭에 표시된다.
- 세트 메뉴는 카테고리 탭에 섞이지 않는다.
- 장바구니에 단품과 세트를 함께 담아도 ID 충돌이 없다.
- 매장/포장 선택에 따라 노출 상품이 달라진다.
- 품절 상품은 표시되지만 추가 버튼이 비활성화된다.
