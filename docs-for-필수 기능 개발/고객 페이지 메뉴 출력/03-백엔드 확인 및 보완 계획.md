# 백엔드 확인 및 보완 계획

## 이미 구현된 API

고객 상품 조회:

```txt
GET /api/customer/sale-products
```

지원 쿼리:

```txt
orderType=DINE_IN|TAKEOUT
section=ALL|SET|MENU
categoryId
```

응답:

```txt
SALE_MENU
SALE_MENU_SET
```

## 확인할 보안 설정

고객 상품 조회는 비로그인 허용이 필요하다.

이미 허용된 항목:

```txt
GET /api/customer/sale-products
```

추가 검토:

```txt
GET /api/sale-menu-categories
```

고객 화면이 카테고리 탭을 구성하려면 카테고리 목록도 고객 접근이 가능해야 한다.

선택지:

1. 기존 `GET /api/sale-menu-categories`를 비로그인 허용
2. 고객용 카테고리 API `GET /api/customer/sale-menu-categories` 추가

MVP 권장:

```txt
GET /api/sale-menu-categories permitAll
```

이 API는 카테고리 이름/노출 순서만 내려주므로 고객 화면 노출에 적합하다. 단, 관리자용 생성/수정/삭제는 기존 권한을 유지한다.

## 고객 카테고리 필터

고객 화면에 표시할 카테고리는 아래 조건이 필요하다.

```txt
visible = true
displayOrder ASC, id ASC
```

현재 카테고리 API가 전체를 내려준다면 프론트에서 `visible` 필터링을 우선 적용한다. 더 엄격하게 하려면 백엔드 고객용 카테고리 API를 추가한다.

## 상품 노출 조건

고객 상품 API 조건:

```txt
visible = true
status in (ACTIVE, SOLD_OUT)
orderType에 맞는 available_dine_in / available_takeout = true
```

주문 가능 조건:

```txt
visible = true
status = ACTIVE
orderType 가능
```

## 후속 주문 API 연동 시 필요

주문 생성 요청:

```json
{
  "orderType": "DINE_IN",
  "items": [
    {
      "type": "SALE_MENU_SET",
      "id": 1,
      "quantity": 1
    },
    {
      "type": "SALE_MENU",
      "id": 3,
      "quantity": 2
    }
  ]
}
```

가격과 구성은 서버에서 재조회해 스냅샷으로 저장한다.
