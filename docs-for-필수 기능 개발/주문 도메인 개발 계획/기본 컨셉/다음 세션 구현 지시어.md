# 다음 세션 구현 지시어

## 목표

주문 도메인 MVP를 구현한다.

현재 고객 키오스크는 실제 상품 조회와 장바구니까지 구현되어 있다.
다음 세션에서는 장바구니를 실제 주문으로 저장하는 API와 프론트 연동을 구현한다.

핵심 목표:

```txt
장바구니에 담기
-> 주문 접수하기 클릭
-> POST /api/customer/orders
-> orders / order_items / order_item_components 저장
-> 성공 응답
-> 장바구니 초기화
```

결제 연동, 주방 상태 변경, 주문 취소, 재고 차감은 제외한다.

## 백엔드 필수 검증

프론트에서 이미 거르더라도 백엔드에서 반드시 다시 검증한다.

단품 `SALE_MENU`:

```txt
sale_menus id 존재
visible = true
status = ACTIVE
orderType = DINE_IN 이면 availableDineIn = true
orderType = TAKEOUT 이면 availableTakeout = true
quantity >= 1
```

세트 `SALE_MENU_SET`:

```txt
sale_menu_sets id 존재
visible = true
status = ACTIVE
orderType = DINE_IN 이면 availableDineIn = true
orderType = TAKEOUT 이면 availableTakeout = true
세트 구성 item이 1개 이상 존재
quantity >= 1
```

MVP에서는 세트 구성 단품의 현재 `status`는 주문 가능 여부에 직접 반영하지 않는다.
세트는 독립 판매 상품이고, 세트 판매 가능 여부는 `sale_menu_sets.status`로 통제한다.

주문 item 하나라도 검증 실패하면 주문 전체를 저장하지 않는다.

## 저장 원칙

프론트 요청은 이것만 받는다.

```json
{
  "orderType": "DINE_IN",
  "items": [
    {
      "type": "SALE_MENU_SET",
      "id": 1,
      "quantity": 2
    }
  ]
}
```

프론트에서 받은 가격/이름/구성은 절대 저장에 사용하지 않는다.

서버가 DB에서 재조회해서 저장한다.

저장:

```txt
orders
order_items
order_item_components
```

`order_items`:

```txt
item_type
sale_menu_id 또는 sale_menu_set_id
item_name
unit_price
quantity
line_total
display_order
```

`order_item_components`:

```txt
세트 주문 item에만 저장
component_name
quantity
display_order
```
