# 결제 취소 및 환불 도메인 개발

작성일: 2026-05-08

## 목적

결제 완료된 주문을 직원이 현장에서 환불 처리하고, 주문 보드와 매출 화면에 환불 상태와 금액을 반영한다.

이번 MVP에서는 PG 취소 연동을 하지 않는다. 서버는 현장 환불 기록만 남긴다.

## 범위

- 대상 주문: `OrderStatus.COMPLETED`
- 대상 결제: `PaymentStatus.PAID`
- 환불 결과:
  - `Order`: `COMPLETED -> CANCELED`
  - `Payment`: `PAID -> REFUNDED`
  - 환불 처리 시각과 처리자 기록
  - 직원 주문 보드 WebSocket 갱신
  - 매출 화면 환불 금액/건수/목록 반영

## 현재 코드 기준 주의점

- 프론트엔드 경로는 `restaurant-book-client`가 아니라 `restaurant-book-front`다.
- 운영 주문 컨트롤러는 `OperationsController`가 아니라 `OperationsOrderController`다.
- WebSocket 전파는 `OrderEventPublisher`가 아니라 `OrderBroadcaster`를 재사용한다.
- 현재 서버는 Flyway 마이그레이션 디렉터리가 없고 `spring.jpa.hibernate.ddl-auto: update`를 사용한다. 운영 DB를 고려하면 별도 SQL은 문서에 남기되, 현재 코드 작업의 필수 파일은 아니다.
- 예외 처리는 `EntityNotFoundException`보다 기존 패턴인 `BusinessException`과 `ErrorCode`를 따른다.

## 권장 작업 순서

1. 백엔드 도메인/API를 먼저 구현해 환불 상태 전이를 고정한다.
2. 매출 API 응답을 확장해 프론트가 사용할 계약을 확정한다.
3. 프론트 타입/API/화면을 계약에 맞춰 연결한다.
4. 환불 성공, 중복 환불 실패, 매출 반영, WebSocket 갱신을 검증한다.
