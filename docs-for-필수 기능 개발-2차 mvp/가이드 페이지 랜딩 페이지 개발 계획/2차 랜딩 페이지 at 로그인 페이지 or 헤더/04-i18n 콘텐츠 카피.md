# 04. i18n 콘텐츠 카피

## 목표

랜딩 전용 네임스페이스 `landing`을 추가한다. ko/en을 1차 정본으로, ja/zh는 키만 등록 후 ko 폴백.

## 1. 네임스페이스 등록

[src/shared/i18n/index.ts](../../../../restaurant-book-front/src/shared/i18n/index.ts)의 `ns` 배열에 `landing` 추가.

```ts
ns: ["common", "nav", "auth", "form", "guide", "landing"],
```

각 언어 [resources/{ko,en,ja,zh}/index.ts](../../../../restaurant-book-front/src/shared/i18n/resources)에서 `landing` export.

## 4. 일본어 / 중국어

빈 객체로 시작. 추후 번역 발주.

```ts
// resources/ja/landing.ts
export const landing = {}; // TODO: i18n - landing ja translation
```

`fallbackLng: "ko"`(또는 `"en"`)에 의존해 ko 카피가 노출되도록 한다. 구체 결정은 [04 1차 i18n](../1차%20가이드%20페이지%20with%20헤더%20버튼/04-i18n%20콘텐츠%20카피.md)에서의 정책과 동일하게.

> 참고: 일본 / 중국 시장을 1차 타겟으로 한다면 ja/zh도 정본 카피가 필요하지만, **2차 작업 범위 밖**으로 둔다.

## 5. 카피 톤 가이드 (작성 시 참고)

- 서술 주어는 "당신/우리"보다 "주문/매출/직원" 같은 시스템 주체로 잡는다.
- 한국어는 단정형(-습니다) 통일.
- 영어는 짧은 문장, 과장 부사(amazing/super) 금지.
- 같은 단어 반복 피하기 — `flow` `update` `aggregate`는 한 섹션에서 한 번만.

## 6. 검증

- [ ] ko/en 모두 hero/values/screens/features/howItWorks/bottomCta/footer가 번역됨
- [ ] ja/zh 전환 시 ko 폴백, missing key 콘솔 경고만
- [ ] 키 그대로 노출되는 곳 없음
- [ ] 카피에 등장하는 기능이 모두 1·2차 MVP에서 실제 구현됐는지 [구현 현황 문서](../../../docs-for-프로젝트%20관리/구현%20현황)와 1:1 대조
