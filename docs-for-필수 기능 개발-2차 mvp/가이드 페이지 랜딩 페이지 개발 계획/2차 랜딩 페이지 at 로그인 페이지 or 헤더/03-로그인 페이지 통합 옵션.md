# 03. 로그인 페이지 통합 옵션

## 목표

로그인 페이지에서 "서비스가 뭔지 궁금한 사람"이 자연스럽게 랜딩으로 흘러갈 수 있게 한다.
이 문서는 [01 노출 전략](./01-노출%20전략%20(어디서%20보여줄까).md)에서 결정한 라우팅(루트 = 랜딩)을 전제로 한다.

## 현재 로그인 페이지 구조

[src/app/login/page.tsx](../../../../restaurant-book-front/src/app/login/page.tsx):

```tsx
<AuthLayout title={t("signInTitle")} subtitle={t("signInSubtitle")}>
  <LoginForm nextPath={nextPath} />
</AuthLayout>
```

[AuthLayout](../../../../restaurant-book-front/src/shared/ui/AuthLayout.tsx)은 hero 이미지 패널 + 폼 패널의 좌우 분할 구조 (최근 커밋 `67d5b84`, `8129863`로 hero 패널 비율을 다듬었음).

## 결정: 로그인 페이지에 랜딩 진입 링크 추가

### A. hero 패널 하단에 1줄 추가 (권장)

```tsx
// AuthLayout.tsx hero 영역 하단
<div className="mt-6 text-sm text-muted-foreground">
  <Link href="/" className="underline hover:text-foreground">
    {t("auth.viewLandingLink")}  {/* "서비스 소개 보기 →" */}
  </Link>
</div>
```

- **장점**: 폼은 건드리지 않음. hero 영역만 추가.
- **단점**: 모바일에서 hero 패널이 접히면 묻힐 수 있음 — 모바일 레이아웃 점검 필요.

### B. 로고 클릭 = 랜딩 (보조)

[AuthLayout](../../../../restaurant-book-front/src/shared/ui/AuthLayout.tsx)에 로고가 노출된다면, 로고를 `Link href="/"`로 감싼다.
이미 그렇게 되어 있을 가능성이 높음 — 코드 확인 후 누락이면 추가.

### C. 회원가입 링크 위에 "서비스가 처음이신가요? 소개 보기" 한 줄

```tsx
// LoginForm 하단 (이미 있을 회원가입 링크 위)
<p className="text-sm text-center text-muted-foreground">
  <Link href="/">{t("auth.firstTimeIntro")}</Link>
</p>
```

전환 동선상 이게 가장 잘 보일 수 있음 — 폼 안의 자연스러운 시선 흐름에 들어옴.

### 권장: A + C 둘 다

- A: hero 영역 → 시각적 안내.
- C: 폼 영역 → 행동 유도 직전 시선.

두 자리에 모두 두되, 카피를 다르게 한다 (반복 방지).
- A: "서비스 소개 보기 →"
- C: "처음이신가요? 우리 시스템 둘러보기"

## 회원가입 페이지에서도 동일 처리

[src/app/register](../../../../restaurant-book-front/src/app/register)도 같은 `AuthLayout`을 쓰고 있을 가능성이 높음.
hero 영역에 "서비스 소개 보기" 링크 동일하게 노출하면 일관성 유지.

## 카피 추가 (i18n)

[src/shared/i18n/resources/ko/auth.ts](../../../../restaurant-book-front/src/shared/i18n/resources/ko/auth.ts)에 추가:

```ts
export const auth = {
  // ...
  viewLandingLink: "서비스 소개 보기 →",
  firstTimeIntro: "처음이신가요? 우리 시스템 둘러보기",
};
```

영어:

```ts
viewLandingLink: "About this service →",
firstTimeIntro: "First time here? Take a quick tour",
```

ja/zh는 키만 등록하고 ko 폴백.

## 로그인된 사용자가 `/login`을 직접 열었을 때

- 기존 동작 유지 (`AuthInitializer`/리다이렉트 흐름이 처리).
- 랜딩 진입 링크는 어차피 보일 일이 없음.

## 모바일 점검 포인트

- hero 패널이 접히는 브레이크포인트 확인 ([AuthLayout](../../../../restaurant-book-front/src/shared/ui/AuthLayout.tsx)).
- 접혔을 때 A 링크가 어디로 가는지 — **폼 위 또는 폼 아래**에 노출되도록 모바일 한정 자리 보장.
- 자리가 충돌하면 모바일은 C만 노출하고 A는 데스크톱 전용으로.

## 검증 포인트 (이 통합에 한정)

- [ ] 데스크톱 `/login` → hero에 "서비스 소개 보기" 노출, 클릭 시 `/`로 이동
- [ ] 모바일 `/login` → A 또는 C 중 최소 하나는 시각적으로 가려지지 않음
- [ ] 데스크톱 `/login` → 폼 하단에 "처음이신가요? 둘러보기" 노출
- [ ] `/register`도 동일 노출
- [ ] 로그인 후 `/login`을 다시 열려고 하면 기존대로 역할 홈으로 리다이렉트됨
