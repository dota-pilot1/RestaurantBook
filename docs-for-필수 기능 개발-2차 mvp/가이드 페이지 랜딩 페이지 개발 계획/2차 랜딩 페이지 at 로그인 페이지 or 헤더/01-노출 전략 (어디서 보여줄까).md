# 01. 노출 전략 (어디서 보여줄까)

## 목표

랜딩 페이지의 라우트와 진입 동선을 결정한다. 후속 문서들은 이 결정에 의존한다.

## 결정해야 하는 것

1. 랜딩 페이지의 URL
2. 비로그인 방문자가 루트(`/`)로 들어왔을 때 어디로 보낼지
3. 로그인된 사용자가 랜딩을 직접 열었을 때 어떻게 다룰지
4. 헤더와 로그인 페이지에서의 진입 링크

## 옵션 비교

### A. 루트 `/` 비로그인 시 랜딩, 로그인 시 역할 홈 (권장)

```
GET /
├─ 비로그인 → 랜딩 페이지 렌더
└─ 로그인 → getRoleHomePath(user.role.code)로 replace
```

- **장점**: 마케팅 측면에서 가장 자연스럽다 (smart-fnb-design.com 한 도메인 = 랜딩).
- **단점**: 기존 [src/app/page.tsx](../../../../restaurant-book-front/src/app/page.tsx)의 동작 변경 필요.
- **변경 범위**: 작음 — 기존 `else if (status === "anonymous") router.replace("/login")` 한 줄을 랜딩 렌더로.

### B. `/about`을 별도 라우트로 두기

```
GET /              → 기존 동작 유지 (비로그인은 /login)
GET /about         → 랜딩 (비로그인 전용)
```

- **장점**: 변경 범위 가장 작음. SEO에서 `/about`이라는 명시적 의미.
- **단점**: 도메인 첫 인상이 여전히 로그인 폼 — 전환에 불리.

### C. 둘 다 — `/`는 랜딩, `/about`도 같은 랜딩

- A의 장점 + 직링크 호환.
- 콘텐츠 중복은 `/about`을 `/`로 영구 redirect하면 해결.

## 권장: 옵션 A + `/about` redirect

- **루트 노출**이 마케팅 ROI가 가장 좋다.
- `/about`으로 직링크 거는 사람이 있을 수 있으니 `/about → /` redirect만 추가.

### 동작 정의

[src/app/page.tsx](../../../../restaurant-book-front/src/app/page.tsx)를 다음 구조로 바꾼다.

```tsx
"use client";

import { useEffect } from "react";
import { useRouter } from "next/navigation";
import { useAuth } from "@/entities/user/model/authStore";
import { getRoleHomePath } from "@/entities/user/lib/roleRoutes";
import { LandingPage } from "@/features/landing/ui/LandingPage";

export default function RootPage() {
  const { status, user } = useAuth();
  const router = useRouter();

  useEffect(() => {
    if (status === "authenticated" && user) {
      router.replace(getRoleHomePath(user.role.code));
    }
  }, [status, user, router]);

  // pending: 빈 화면 (깜빡임 방지)
  if (status === "pending") return null;
  // authenticated: 위에서 replace 했으므로 잠깐 빈 화면
  if (status === "authenticated") return null;

  // anonymous: 랜딩 렌더
  return <LandingPage />;
}
```

`/about`은 별도 page에서 `redirect("/")`.

```tsx
// src/app/about/page.tsx
import { redirect } from "next/navigation";
export default function AboutRedirect() {
  redirect("/");
}
```

## 헤더에서의 노출

### 비로그인 사용자

비로그인 상태에서는 헤더에 다음만 노출:

| 항목 | 동작 |
| --- | --- |
| 로고 / 브랜드 | `/` (랜딩) |
| 사용 가이드 | **숨김** (1차 결정 — 가이드는 로그인 사용자 전용) |
| 로그인 / 회원가입 | 기존 그대로 |

→ 별도 "서비스 소개" 메뉴는 만들지 않는다. 로고가 곧 랜딩이다.

### 로그인 사용자

루트(`/`)는 역할 홈으로 자동 이동되므로, 헤더에 "랜딩 보기" 같은 메뉴는 없다.
관리자만이라도 랜딩 미리보기가 필요하면 `/about`을 별도로 두지 말고, 운영자 도구에서 "랜딩 보기 (새 탭)" 버튼을 두는 정도로 충분하다 — **1차 작업에서는 안 한다**.

## 회원가입 페이지

기존 [register](../../../../restaurant-book-front/src/app/register) 그대로 유지. 랜딩의 CTA가 이쪽으로 흘러가는 종착지.

## SEO / OG

- 루트 페이지에 `metadata`(title, description, openGraph) 설정.
- 한국어/영어 모두 `lang` 속성 정상화.
- 정적 OG 이미지 1장 추가 (`/public/og.png`).
- `robots.txt`에서 `/login`, `/register`, `/dashboard` 등 운영 라우트 disallow 고려.

## 검증 포인트 (이 결정에 한정)

- [ ] 비로그인 + `/` → 랜딩 렌더
- [ ] 로그인 + `/` → 역할 홈으로 이동
- [ ] `/about` → `/`로 redirect
- [ ] 비로그인 헤더에 "사용 가이드" 안 보임 (1차 합의 그대로)
- [ ] 로그인 페이지에 "서비스 소개" 링크 노출
