# 2차: 서비스 랜딩 페이지 (로그인 페이지 or 헤더)

작성일: 2026-05-08

## 목적

비로그인 상태의 방문자(잠재 고객 = 식당 사장님/매니저)에게 "이 시스템이 뭘 해주는가"를 보여주는 마케팅·소개용 랜딩 페이지를 만든다.
1차 가이드(`/guide`)가 **이미 일하는 사람**을 위한 매뉴얼이라면, 2차 랜딩은 **아직 안 쓰는 사람**을 위한 소개다.

## 1차와의 관계

| 항목 | 1차 가이드 | 2차 랜딩 |
| --- | --- | --- |
| 대상 | 로그인된 사용자 | 비로그인 방문자 |
| URL | `/guide`, `/guide/{role}` | `/`(redirect 변경) 또는 `/about` |
| 진입 | 헤더 "사용 가이드" | 루트 도메인 / 로그인 페이지 링크 |
| 핵심 | 운영 매뉴얼 | 가치 제안, 스크린샷, CTA |
| 분량 | 짧고 압축 | 스크롤 5~7섹션 (랜딩 표준) |

1차가 운영되고 있어야 2차의 "핵심 기능 보기"를 자연스럽게 가이드로 연결할 수 있다.

## 범위 (이번 2차에 하는 것)

- 라우트 추가: `/about` (또는 루트 `/` 비로그인 시 노출 — [01 문서](./01-노출%20전략%20(어디서%20보여줄까).md)에서 결정)
- 헤더와 로그인 페이지에서 진입 동선 마련
- 섹션 구성:
  1. Hero (서비스명 + 한 줄 가치 제안 + CTA)
  2. 핵심 가치 3개 카드
  3. 주요 화면 미리보기 (키오스크/주방/직원)
  4. 기능 목록 (간단)
  5. 도입 흐름 / 문의 / CTA 반복
- i18n: ko/en/ja/zh 키 등록 (ko/en 카피 정본)
- 비로그인 사용자에게만 노출, 로그인된 사용자에게는 자동 리다이렉트(혹은 헤더 메뉴 비노출)

## 범위 밖

- 결제/플랜 페이지 (가격표) — 비즈니스 모델 확정 후 별도
- 블로그 / 사례 / 도큐 사이트
- 회원가입 흐름 자체의 변경 (회원가입 페이지는 그대로)
- 외부 마케팅 사이트(별도 도메인) 분리

## 권장 작업 순서

1. **노출 전략 결정** ([01](./01-노출%20전략%20(어디서%20보여줄까).md)) — 어디 노출할지부터 정해야 라우팅이 안 흔들린다.
2. **Hero + CTA 한 섹션** — 다른 섹션은 placeholder로 두고 hero만 실제 카피로 굳힌다.
3. **나머지 섹션** — 카드/스크린샷/기능 목록/도입 흐름.
4. **로그인 페이지 진입 링크** — `/login`의 hero 영역에 "서비스 소개" 링크 1줄.
5. **i18n + SEO 메타** — 한국어/영어 카피 + `metadata` 설정.
6. **검증** — 비로그인/로그인 동선, 반응형, 다국어, OG 태그.

## UI/UX 원칙 (랜딩 표준)

- **Above the fold**: hero에서 7초 안에 "뭐 하는 서비스인지" 이해돼야 한다.
- **CTA**: 첫 hero와 마지막 섹션 두 번 노출. 1차 CTA = "회원가입", 보조 = "로그인".
- **스크린샷**: 실제 화면 캡처 우선. 없으면 mockup. 텍스트로만 채우지 않는다.
- **속도**: 이미지는 `next/image`, hero는 LCP 최적화 (priority).
- **다크 톤이 기본** — 식당 운영 화면(직원 보드/주방)도 다크 테마가 가독성이 좋아 그쪽 톤과 맞춘다. 라이트도 선택 가능.

## 1차와 2차의 카피 톤 차이 (의식적으로 분리)

- **1차 가이드 톤**: 사실·동사구. "메뉴 담기", "결제 (CARD/CASH/ETC)".
- **2차 랜딩 톤**: 결과·이익. "주문 누락 0", "직원이 더 빨리 응답합니다".

같은 기능이라도 카피의 단어를 다르게 쓴다. (1차에서 `RECEIVED → ACCEPTED` 같은 상태명 쓰는 자리에서, 2차는 "주문 누락 없이 흐름으로 흘러갑니다"로.)
