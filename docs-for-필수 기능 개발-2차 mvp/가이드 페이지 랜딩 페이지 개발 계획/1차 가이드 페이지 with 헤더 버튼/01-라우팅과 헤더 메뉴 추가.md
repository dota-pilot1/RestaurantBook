# 01. 라우팅과 헤더 메뉴 추가

## 목표

`/guide` 진입점을 만들고, 헤더 어디서나 한 번에 갈 수 있게 한다.
세부 콘텐츠 없이도 라우트와 메뉴 노출이 동작하는 "셸"을 먼저 완성한다.

## 1. 라우트 구조

App Router 디렉터리 기준으로 추가한다.

```
restaurant-book-front/src/app/
└── guide/
    ├── layout.tsx        # 가이드 공통 레이아웃 (좁은 컨테이너 + 인증 가드)
    ├── page.tsx          # 메인 (플로우 + 역할 카드 3개)
    ├── staff/
    │   └── page.tsx      # 직원 상세
    ├── kitchen/
    │   └── page.tsx      # 주방 상세
    └── customer/
        └── page.tsx      # 고객 상세
```

### 1.1 `guide/layout.tsx`

- 클라이언트 컴포넌트.
- `useAuth()` 결과 `status === "anonymous"`이면 `router.replace("/login?next=/guide")`.
- 로그인 상태 확정 전(초기 `pending`)에는 빈 placeholder 렌더 (깜빡임 방지).
- 컨테이너는 `max-w-5xl mx-auto px-4 py-8` 정도로 [AuthLayout](../../../../restaurant-book-front/src/shared/ui/AuthLayout.tsx)과 결을 맞춘다.

### 1.2 각 `page.tsx`

- 1단계에서는 `<h1>가이드 메인</h1>` 같은 placeholder만 두고, 콘텐츠는 02·03 문서에서 채운다.

## 2. 헤더 메뉴 추가

[Header.tsx](../../../../restaurant-book-front/src/widgets/header/ui/Header.tsx)는 두 가지 소스로 메뉴를 만든다:

- 서버 응답 `navigationMenuApi.list()`
- 폴백 `fallbackNavigationMenus`

가이드 메뉴는 **두 곳 모두에 등록**해야 일관된다.

### 2.1 폴백 상수에 추가

`fallbackNavigationMenus` 배열 끝에 추가 — `requiredRole`을 비워서 로그인된 모든 사용자에게 노출.

```ts
{
  id: -100,
  code: "GUIDE",
  parentId: null,
  label: "사용 가이드",
  labelKey: "nav.guide",
  path: "/guide",
  icon: "BookOpen",
  isExternal: false,
  requiredRole: null,
  requiredPermission: null,
  visible: true,
  displayOrder: 99,
  createdAt: "",
  updatedAt: "",
},
```

`displayOrder: 99`로 두어 다른 메뉴 뒤에 배치한다.
아이콘 `BookOpen`은 `lucide-react`에 존재하는지 확인 후 `import`에 추가한다 (`Header.tsx` 상단의 `lucide-react` import 블록 갱신).

### 2.2 서버 메뉴(`navigation_menus` 테이블)에 동일 row 시드

운영 DB에는 코드로 안 들어가므로, 다음 두 가지 중 택1:

- **권장**: 관리자가 `/navigation-menus` 화면에서 1건 추가 (운영 후 변경 자유로움).
- **선택**: 백엔드 시더에 추가 — 가이드는 정적이고 자주 안 바뀌니 시더 추가도 무방하다. 작업한다면 [`NavigationMenuSeeder`](../../../../restaurant-book-server/src/main/java/com/cj/restaurantbook/config) 류에 같은 값으로 row 추가.

### 2.3 익명 사용자 노출 차단

현재 헤더의 `buildTree`는 `requiredRole`이 비면 모두에게 보여준다. 비로그인 사용자에게는 가이드를 숨겨야 한다.

옵션 A — 폴백/서버 데이터 둘 다 `requiredRole` 사용 안 하고, 헤더에서 분기:

```ts
// Header.tsx 안에서, 메뉴 트리 빌드 직전
const isAuthenticated = status === "authenticated";
const sourceMenus = isAuthenticated
  ? menus
  : menus.filter((m) => m.code !== "GUIDE");
```

옵션 B — `buildTree`에 익명 처리 규칙 추가 (`requiredRole === null && code === "GUIDE"`인 메뉴는 익명에게 숨김).

**옵션 A를 권장**: 변경 범위가 작고 `buildTree` 책임을 늘리지 않는다.

## 3. i18n 키 등록

`nav.ts`에 `guide` 키 추가.

`restaurant-book-front/src/shared/i18n/resources/ko/nav.ts`:

```ts
export const nav = {
  // ...
  guide: "사용 가이드",
};
```

영/일/중 동일 위치에 키만 등록 (자세한 문구는 [04-i18n 콘텐츠 카피.md](./04-i18n%20콘텐츠%20카피.md)).

## 4. 결과 검증

- 헤더에 "사용 가이드" 버튼이 보이고 `/guide`로 이동.
- 비로그인 → 헤더에서 안 보임. 직접 `/guide`로 들어가도 `/login?next=/guide`로 리다이렉트.
- 4개 언어 전환 시 라벨이 즉시 바뀜.
- 다크/라이트 테마 전환 시 헤더에서 깨짐 없음.
