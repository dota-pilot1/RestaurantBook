# 02. 가이드 메인 페이지 (플로우 + 카드)

## 목표

`/guide` 메인을 한 화면에서 "주문 1건의 여정"과 "내 역할 진입점"이 동시에 보이는 1페이지로 만든다.

## 레이아웃

```
┌─────────────────────────────────────────────┐
│ Hero                                         │
│  제목 — "한 주문이 우리 가게에서 흐르는 길"     │
│  부제 — 한 줄 카피                             │
│  [고객] ──▶ [주방] ──▶ [직원] ──▶ [결제 완료]  │
│   클릭 가능 (해당 역할 상세로 이동)              │
└─────────────────────────────────────────────┘

┌──────────┐ ┌──────────┐ ┌──────────┐
│ 🧑 고객   │ │ 👨‍🍳 주방  │ │ 🧑‍💼 직원  │
│           │ │           │ │           │
│ 핵심 3단계 │ │ 핵심 3단계 │ │ 핵심 4단계 │
│           │ │           │ │           │
│ [자세히 →] │ │ [자세히 →] │ │ [자세히 →] │
└──────────┘ └──────────┘ └──────────┘

▾ 관리자 메뉴는 어디서 봐요? (접힘)
   - 주문 관리, 매출, 매니저 대시보드, 메뉴/카테고리, ...
```

## 1. Hero — 주문 흐름 다이어그램

### 1.1 의도

- 신규 직원이 5초 안에 "이 가게에서 주문이 어떻게 흐르나"를 본다.
- 각 노드 클릭 → 해당 역할의 상세 페이지.

### 1.2 데이터 모델

```ts
// src/features/guide/data/orderFlow.ts
type FlowNode = {
  key: "customer" | "kitchen" | "staff" | "complete";
  labelKey: string;        // i18n 키
  href?: string;           // /guide/{role} (complete는 링크 없음)
  icon: LucideIcon;
};

export const orderFlow: FlowNode[] = [
  { key: "customer", labelKey: "guide.flow.customer", href: "/guide/customer", icon: ShoppingBag },
  { key: "kitchen",  labelKey: "guide.flow.kitchen",  href: "/guide/kitchen",  icon: Utensils },
  { key: "staff",    labelKey: "guide.flow.staff",    href: "/guide/staff",    icon: BadgeCheck },
  { key: "complete", labelKey: "guide.flow.complete", icon: CheckCircle2 },
];
```

### 1.3 컴포넌트

- `src/features/guide/ui/OrderFlow.tsx`
- 가로(데스크톱) / 세로(모바일) 자동 전환 — `flex-row md:flex-col`이 아니라 **`flex-col md:flex-row`** (모바일은 세로가 자연스러움).
- 각 노드: 아이콘 + 라벨 + (있으면) 화살표 `→` (모바일은 `↓`).
- `href` 있는 노드는 `Link`로 감싸기.

### 1.4 카피 (한국어 기준)

| 키 | 문구 |
| --- | --- |
| `guide.hero.title` | 한 주문이 우리 가게에서 흐르는 길 |
| `guide.hero.subtitle` | 고객의 주문이 어떻게 주방을 거쳐 결제까지 이어지는지 한눈에 보세요 |
| `guide.flow.customer` | 고객 주문 |
| `guide.flow.kitchen` | 주방 조리 |
| `guide.flow.staff` | 직원 서빙 |
| `guide.flow.complete` | 결제 완료 |

## 2. 역할 카드 3개

### 2.1 데이터 모델

```ts

type RoleCard = {

### 2.2 카드 카피 (한국어 기준 / 실제 구현 기능 기반)

| 키 | 문구 |
| --- | --- |
| `guide.cards.customer.title` | 고객 |
| `guide.cards.customer.desc` | 키오스크에서 메뉴를 담고 직원을 부르세요 |
| `guide.cards.customer.step1` | 메뉴 담기 (수량 선택 시 우상단 체크 표시) |
| `guide.cards.customer.step2` | 매장/포장 선택 후 주문 |
| `guide.cards.customer.step3` | 직원 호출 또는 주문 취소 |
| `guide.cards.kitchen.title` | 주방 |
| `guide.cards.kitchen.desc` | 신규 주문을 접수하고 조리 상태를 갱신하세요 |
| `guide.cards.kitchen.step1` | 신규 주문 접수 (RECEIVED → ACCEPTED) |
| `guide.cards.kitchen.step2` | 조리 시작 (ACCEPTED → COOKING) |
| `guide.cards.kitchen.step3` | 준비 완료 (COOKING → READY) |
| `guide.cards.staff.title` | 직원 |
| `guide.cards.staff.desc` | 준비 완료 주문을 결제 처리하고 호출에 응답하세요 |
| `guide.cards.staff.step1` | 준비 완료 주문 확인 |
| `guide.cards.staff.step2` | 결제 (CARD/CASH/ETC) |
| `guide.cards.staff.step3` | 결제 완료 후 환불(필요 시) |
| `guide.cards.staff.step4` | 직원 호출 알림 처리 |

### 2.3 컴포넌트

- `src/features/guide/ui/RoleCard.tsx`
- props: `RoleCard` 타입.
- 카드 자체가 `Link href={card.href}` — 카드 전체가 클릭 가능.
- accent별 컬러 매핑은 `src/features/guide/ui/accent.ts`에 토큰화 (Tailwind 임의 클래스 동적 생성 금지).

```

### 2.4 그리드

- 데스크톱: 3열 (`grid-cols-3`).
- 태블릿: 3열 유지 (식당 태블릿 가로 1024 이상 가정).
- 모바일: 1열 (`grid-cols-1 md:grid-cols-3`).

## 3. 관리자 메뉴 링크 (접힘)

```tsx
<details className="mt-12 rounded-lg border border-border p-4">
  <summary className="cursor-pointer font-medium">{t("guide.admin.summary")}</summary>
  <ul className="mt-3 grid gap-2 sm:grid-cols-2">
    {adminLinks.map(link => (
      <li key={link.href}><Link href={link.href}>{t(link.labelKey)}</Link></li>
    ))}
  </ul>
</details>
```

`adminLinks`는 `Header.tsx`의 `fallbackNavigationMenus` 중 관리자 카테고리만 추출해 단일 평면 리스트로 정리.

| 키 | 문구 |
| --- | --- |
| `guide.admin.summary` | 관리자 메뉴는 어디서 봐요? |

링크 카피는 기존 `nav.*` 키를 그대로 재사용 (중복 카피 방지).

## 4. 인증 가드 동작

- `layout.tsx`에서 비로그인을 차단하므로 메인 페이지는 로그인 가정.
- 사용자의 역할(`user.role.code`)을 보고 본인 역할 카드를 강조 표시 (얇은 outline + "내 역할" 뱃지). 강조 로직은 카드 props가 아니라 메인 페이지 안에서 처리.
