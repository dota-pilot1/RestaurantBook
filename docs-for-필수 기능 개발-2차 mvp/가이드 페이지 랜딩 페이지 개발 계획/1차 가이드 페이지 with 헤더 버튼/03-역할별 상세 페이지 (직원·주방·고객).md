# 03. 역할별 상세 페이지 (직원·주방·고객)

## 목표

각 상세 페이지는 "내가 이 화면에서 1교대 동안 하게 될 일"을 5분 안에 익히도록 한다.
스크린샷 1~2장 + 단계 설명 + 자주 만나는 상황(2~3개).

## 공통 구조

```
[breadcrumb]  사용 가이드 / {역할}

# {역할 제목}
{한 줄 설명}

## 핵심 화면 (스크린샷)
└ <ScreenShot src=... caption=... />

## 작업 순서
1. ...
2. ...
3. ...

## 자주 만나는 상황
- 상황 1: ...
- 상황 2: ...

[다른 역할 보기 →]  [고객] [주방] [직원]
```

## 공통 컴포넌트

### `<GuideSection title>{children}</GuideSection>`
- 섹션 제목 + 카드 컨테이너. 모든 상세 페이지에서 동일.

### `<ScreenShot src caption />`
- `next/image` 사용. 최대 너비 880px. 이미지 미준비면 placeholder svg.
- 1차에서는 `public/guide/{role}-{n}.png` 자리에 placeholder 사용.

### `<StepList items />`
- `items: { title: string; desc?: string }[]`
- `<ol>`로 렌더, 각 단계는 카드형. 모바일에서도 줄바꿈 자연스럽게.

### `<RoleSwitcher current />`
- 페이지 하단 — 다른 두 역할로 이동하는 버튼 그룹.

배치: `src/features/guide/ui/{GuideSection,ScreenShot,StepList,RoleSwitcher}.tsx`.

## A. 고객 상세 — `/guide/customer`

### 콘텐츠 (한국어 / 실제 구현 기준)

**제목**: 고객
**한 줄 설명**: QR/태블릿으로 주문하고 직원을 부르는 흐름을 알려드립니다.

**핵심 화면**: 키오스크 화면 ([src/features/kiosk/KioskHome.tsx](../../../../restaurant-book-front/src/features/kiosk/KioskHome.tsx))

**작업 순서**

1. **메뉴 담기** — 카테고리에서 메뉴를 골라 수량을 늘리면 카드 우상단에 ✓ 체크가 보입니다.
2. **장바구니 확인** — 매장/포장 선택, 합계 확인.
3. **주문하기** — 주문 후 활성 주문 카드가 노출됩니다.
4. **직원 호출** — "직원 호출" 버튼으로 기본 요청(물/수저/계산 요청)을 체크하거나 직접 메시지를 입력해 보냅니다.
5. **주문 취소** — 주방 접수 전이면 직접 취소 가능.

**자주 만나는 상황**

- 주문 후 메뉴 변경하고 싶을 때 → 직원 호출 → "메뉴 변경" 메시지.
- 콜라처럼 조리가 필요 없는 메뉴는 접수 즉시 "준비 완료"로 바뀝니다 (직원이 가져옵니다).
- 같은 테이블에서 1분 내에 직원을 두 번 부를 수는 없습니다 (서버에서 차단).

**i18n 키 prefix**: `guide.customer.*` (제목/설명/단계/상황 각 항목).

## B. 주방 상세 — `/guide/kitchen`

### 콘텐츠

**제목**: 주방
**한 줄 설명**: 들어온 주문을 접수→조리→완료로 옮기는 보드를 다룹니다.

**핵심 화면**: 주방 보드 ([src/app/kitchen/page.tsx](../../../../restaurant-book-front/src/app/kitchen/page.tsx))

**작업 순서 (주문 상태 전이)**

1. **신규 주문 접수** — `RECEIVED` 컬럼의 카드를 "접수"로 옮깁니다 (`→ ACCEPTED`).
   - 모든 메뉴가 조리 불필요면 자동으로 `READY`로 점프합니다 (예: 콜라).
2. **조리 시작** — `ACCEPTED` 카드를 "조리 시작"으로 옮깁니다 (`→ COOKING`).
3. **준비 완료** — `COOKING` 카드를 "준비 완료"로 옮깁니다 (`→ READY`). 직원 보드로 자동 전달됩니다.
4. **취소** — 재료 부족 등으로 조리 불가능하면 카드의 "취소"를 누릅니다.

**자주 만나는 상황**

- 새 주문이 안 보이면 WebSocket 연결 끊김 가능 — 페이지 새로고침으로 폴링 재개됩니다.
- 세트 메뉴는 구성 메뉴 중 하나라도 조리 필요면 일반 흐름을 따릅니다.

**API 참고** (가이드에 직접 노출은 X, 개발자용 부록만):
`PATCH /api/kitchen/orders/{id}/{accept|start-cooking|ready}`

**i18n 키 prefix**: `guide.kitchen.*`

## C. 직원 상세 — `/guide/staff`

### 콘텐츠

**제목**: 직원
**한 줄 설명**: 준비 완료된 주문을 결제하고 호출에 응답합니다.

**핵심 화면**: 직원 보드 ([src/features/staff-ready-orders/StaffReadyOrders.tsx](../../../../restaurant-book-front/src/features/staff-ready-orders/StaffReadyOrders.tsx))

**작업 순서**

1. **준비 완료 주문 확인** — `READY` 컬럼의 카드를 보고 테이블/포장 여부를 확인.
2. **결제 처리** — 카드 → "결제" → 결제수단 선택 (`CARD` / `CASH` / `ETC`) → 완료. `READY → COMPLETED`.
3. **환불** — 결제 완료 카드의 "환불" → 확인 다이얼로그 → `COMPLETED → CANCELED`, `Payment PAID → REFUNDED`.
4. **직원 호출 응답** — 보드 상단 "호출 알림"에서 미처리 건수 확인 → 다이얼로그에서 테이블/메시지/경과시간 확인 → "처리 완료".
5. **주문 취소** — 결제 전 운영 취소 (예: 손님 변심).

**자주 만나는 상황**

- 같은 주문을 두 번 환불할 수 없습니다 (서버에서 차단).
- 결제 정보가 없는 주문은 환불할 수 없습니다.
- 호출은 처리 완료/취소 시 고객 화면에서 즉시 사라집니다.

**API 참고**:
`PATCH /api/operations/orders/{id}/complete`, `/cancel`, `/refund`
`PATCH /api/operations/staff-calls/{id}/acknowledge`

**i18n 키 prefix**: `guide.staff.*`

## 페이지 구현 골격

각 상세 페이지는 거의 같은 구조이므로 데이터 + 동일 컴포넌트로 통일.

```tsx
// src/app/guide/staff/page.tsx
import { roleGuides } from "@/features/guide/data/roleGuides";
import { GuidePage } from "@/features/guide/ui/GuidePage";

export default function StaffGuidePage() {
  return <GuidePage data={roleGuides.staff} current="staff" />;
}
```

```ts
// src/features/guide/data/roleGuides.ts
type RoleGuide = {
  titleKey: string;
  leadKey: string;
  screenshot: { src: string; captionKey: string };
  steps: { titleKey: string; descKey?: string }[];
  situations: { textKey: string }[];
};
export const roleGuides: Record<"customer"|"kitchen"|"staff", RoleGuide> = { /* ... */ };
```

`<GuidePage>`는 `<GuideSection>`, `<ScreenShot>`, `<StepList>`, `<RoleSwitcher>`를 조립한다.
