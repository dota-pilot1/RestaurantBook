# 키오스크 헤더 네비 on/off 설정 버튼 구현 계획

## 목표

키오스크 화면(`/customer`)에서 상단 헤더 네비게이션을 숨기거나 다시 보이게 하는 설정 기능을 추가한다.

주문 패널 하단의 `직원 호출` 버튼 옆에 톱니바퀴 설정 버튼을 배치하고, 클릭 시 비밀번호 `admin123`을 입력해야 설정 다이얼로그로 진입하게 한다. 설정 다이얼로그에는 `헤더 네비 출력 여부` 스위치를 둔다.

## 권장 UX

- `직원 호출` 버튼 옆에 작은 톱니바퀴 아이콘 버튼을 둔다.
- 톱니바퀴 클릭 시 비밀번호 입력 다이얼로그를 먼저 띄운다.
- 비밀번호가 틀리면 설정 화면으로 넘어가지 않는다.
- 비밀번호가 맞으면 `헤더 네비 출력 여부` 스위치 다이얼로그를 연다.
- 저장 성공 시 토스트를 출력하고 화면에 즉시 반영한다.

## 구현 범위

### 1. 설정 저장 방식

최종적으로는 서버 설정값으로 관리하는 것이 맞다.

- `site_settings.header_nav_visible` 컬럼 추가
- 기본값 `true`
- `GET /api/site-settings` 응답에 포함
- `PUT /api/site-settings` 요청에 포함

단, 현재 `PUT /api/site-settings`는 `ROLE_ADMIN` 전용이다. 키오스크가 비로그인 상태라면 단순히 프론트 비밀번호만으로는 서버 저장이 불가능할 수 있다.

선택지는 3개다.

1. 관리자 로그인 상태의 키오스크 브라우저에서만 저장 허용
2. 서버에 키오스크 전용 비밀번호 검증 API 추가
3. MVP에서는 로컬 저장소로 먼저 구현

운영까지 고려하면 2번이 가장 깔끔하다. 빠른 MVP라면 3번으로 시작하고 이후 서버 설정으로 승격한다.

### 2. Header 처리

파일:

- `restaurant-book-front/src/widgets/header/ui/Header.tsx`

처리:

- `usePathname()`으로 현재 경로 확인
- `/customer` 경로에서만 설정값을 적용
- `headerNavVisible === false`이면 헤더를 숨김

권장 동작:

- 관리자/직원/주방 화면 헤더는 계속 출력
- 키오스크 화면에서만 헤더 전체 on/off

이유:

- 관리자 화면까지 헤더가 사라지면 복구 동선이 끊길 수 있다.
- 요구사항의 원인이 키오스크이므로 범위를 `/customer`에 제한한다.

### 4. 설정 다이얼로그

설정 다이얼로그에는 스위치 하나만 둔다.

- 제목: `키오스크 설정`
- 항목: `헤더 네비 출력 여부`
- 설명: `끄면 키오스크 화면에서 상단 헤더가 숨겨집니다.`
- 버튼: `취소`, `저장`

스위치 값 변경 후 저장 시 설정 API 또는 로컬 저장소를 갱신한다.

### 5. 관리자 설정 화면 반영

파일:

- `restaurant-book-front/src/features/site-settings/SiteSettingsForm.tsx`

관리자도 같은 값을 볼 수 있도록 `헤더 네비 출력 여부` 스위치를 추가한다.

기존 저장 요청에 새 필드가 빠지면 값이 덮일 수 있으므로 `siteSettingApi.update()` 호출 시 반드시 포함한다.

```ts
headerNavVisible: data?.headerNavVisible ?? true
```

## 검증 체크리스트

- `/customer`에서 `직원 호출` 옆 톱니바퀴 버튼이 보인다.
- 톱니바퀴 클릭 시 비밀번호 입력 다이얼로그가 열린다.
- `admin123`이 아니면 설정 다이얼로그가 열리지 않는다.
- `admin123`이면 설정 다이얼로그가 열린다.
- 스위치를 끄고 저장하면 `/customer`에서 헤더가 사라진다.
- 스위치를 켜고 저장하면 `/customer`에서 헤더가 다시 보인다.
- 새로고침 후에도 설정이 유지된다.
- 직원 호출, 주문 접수, 주문 내역 기능은 영향 없이 동작한다.
- `/staff`, `/kitchen`, `/manager`, `/dashboard` 등 관리 화면 헤더는 그대로 보인다.

## 결론

현재 요구사항 기준으로는 `키오스크 화면에서만 헤더 전체 on/off`가 가장 단순하고 안전하다. 톱니바퀴 + `admin123`은 MVP의 현장 오조작 방지용으로 쓰고, 운영 보안이 필요해지면 서버 비밀번호 검증 API로 분리한다.
