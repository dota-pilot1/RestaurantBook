# 00. 개요

## 목표

매니저가 `/sales`에서 기간별 매출, 결제 건수, 환불 금액, 환불 건수, 결제수단별 매출, 최근 결제/환불 기록을 한 화면에서 확인할 수 있게 한다.

현재 화면은 기본 조회 구조가 이미 있으므로, 이번 단계에서는 다음을 우선한다.

1. 매출 집계 기준을 문서와 코드에서 명확히 고정한다.
2. `/sales` UI를 매니저용 통계 화면으로 재구성한다.
3. `/manager`에서 오늘 매출과 환불 상태를 더 잘 드러내고 `/sales`로 자연스럽게 이동하게 한다.
4. 새 도메인/테이블 없이 `Payment` 기반 조회 모델로 끝낸다.

## 구현 판단

**지금 매출 통계부터 구현하는 것이 맞다.**

이유:

- 결제 완료 데이터가 이미 `Payment`로 남는다.
- 환불도 `PaymentStatus.REFUNDED`, `refundedAt`, `refundedBy` 기준으로 추적 가능하다.
- 매니저 대시보드에 오늘 매출 카드가 이미 있어 상세 화면 연결 가치가 크다.
- 새 주문 기능을 더 붙이기 전에 매출 기준을 고정해야 후속 정산/리포트 기능의 기준이 안정된다.

## 도메인 범위

이번 MVP에서는 새 도메인을 만들지 않는다.

유지:

- `Payment`: 매출/환불 원천 데이터
- `SalesService`: 조회 전용 집계 서비스
- `SalesController`: 매출 조회 API

추가하지 않음:

- `Sales` 엔티티
- `DailySales` 집계 테이블
- `Settlement` 정산 도메인
- `Refund` 별도 도메인

## 집계 기준

| 항목 | 기준 |
|------|------|
| 총 매출 | 조회 기간의 `PaymentStatus.PAID` 결제 금액 합계 |
| 결제 건수 | 조회 기간의 `PaymentStatus.PAID` 결제 건수 |
| 환불 금액 | 조회 기간의 `PaymentStatus.REFUNDED` 결제 금액 합계 |
| 환불 건수 | 조회 기간의 `PaymentStatus.REFUNDED` 결제 건수 |
| 순매출 | `총 매출 - 환불 금액`, MVP에서는 프론트 계산 가능 |
| 결제수단별 매출 | `PAID` 결제만 포함 |
| 결제수단별 항목 | 백엔드가 `CARD/CASH/ETC` 3개를 항상 반환하고, 결제가 없으면 0원/0건으로 채운다 |
| 최근 결제 목록 | `paidAt` 기준 최신순, MVP에서는 최근 50건만 반환/표시 |
| 최근 환불 목록 | `refundedAt` 기준 최신순, MVP에서는 최근 50건만 반환/표시 |
| 기간 | Asia/Seoul 영업일 기준, 종료일 inclusive 화면 입력 -> 서버 쿼리는 다음날 0시 exclusive |

## MVP 결정사항

- 목록은 페이징 없이 최근 50건만 표시한다. 화면 제목 또는 보조 문구에 `최근 50건`을 명시한다.
- `REFUNDED` 결제의 `refundedAt`은 반드시 존재해야 한다. 프론트 환불 목록에서는 `paidAt` fallback을 쓰지 않는다.
- 순매출은 `총 매출 - 환불 금액`이다. 어제 결제분이 오늘 환불되면 오늘 순매출은 음수가 될 수 있으며, 이 경우 음수 부호와 경고 색상으로 그대로 표시한다.
- 결제수단별 3개 항목 보장은 백엔드 `SalesService` 책임이다. 프론트는 누락 항목 보강을 기본 로직으로 두지 않고, 필요 시 방어 코드만 둔다.
- `SalesServiceTest`는 필수다. 특히 환불 집계가 `paidAt`이 아니라 `refundedAt` 기준이라는 점을 테스트로 잠근다.
- 권한 회귀는 `/api/sales`, `/api/sales/today-summary` 둘 다 비매니저 계정 403을 검증한다.

## 화면 범위

`/sales`는 기존 UI를 전면 수정해도 된다.

권장 화면 구조:

1. 상단 헤더
   - 뒤로가기
   - 제목: `매출 통계`
   - 보조 문구: 결제/환불 기준 안내
   - 새로고침
2. 기간 필터
   - 오늘
   - 최근 7일
   - 이번 달
   - 직접 선택
3. 핵심 지표
   - 총 매출
   - 순매출
   - 결제 건수
   - 환불 금액/건수
4. 결제수단별 매출
   - 카드/현금/기타 금액과 건수
   - 전체 대비 비중
5. 최근 결제 목록
6. 최근 환불 목록

## 이번 단계에서 하지 않을 것

- 차트 라이브러리 도입
- 엑셀 다운로드
- 일/주/월 단위 서버 집계 API
- 최근 목록 페이징/더보기
- 부분 환불
- 할인/쿠폰/세금 계산
- 영업 마감 스냅샷
- 권한 체계 변경
