# 프로필 페이지 구현 계획

## 목표

프로필 페이지는 당장 표시할 데이터가 적어도 이후 확장에 맞는 기본 골격을 먼저 갖춘다. 프로필 이미지, 기본 정보, 권한, 메모장, 즐겨찾기 영역을 분리해 두고, 추후 API와 저장 기능을 붙여도 레이아웃이 크게 흔들리지 않게 한다.

## 현재 기본 구조

- 좌측 본문 영역: 기본 정보, 보유 권한, 메모장, 즐겨찾기 탭을 표시한다.
- 우측 사이드바: `20rem` 폭으로 프로필 이미지 업로드, 계정 스냅샷, 바로가기를 배치한다.
- 프로필 이미지 영역: 이미지가 있으면 실제 이미지를 표시하고, 없으면 이니셜 플레이스홀더를 표시한다.
- 본문 최대 폭: `max-w-7xl`로 관리 화면들과 비슷한 밀도를 유지한다.

## 이후 확장 포인트

1. 프로필 이미지
   - `User` 응답에 `profileImageUrl` 추가
   - 로그인 사용자용 presigned upload API 연동
   - 이미지 미등록 시 이니셜 플레이스홀더 유지

2. 기본 정보 수정
   - 이름 변경, 이메일 표시/변경 정책 분리
   - 수정 모드는 좌측 기본 정보 카드 내부에서 inline 또는 dialog로 처리
   - 역할은 일반 사용자가 직접 변경하지 않고 읽기 전용으로 유지

3. 개인 메모
   - 로컬 임시 메모에서 서버 저장형 메모로 확장
   - 저장 상태, 마지막 저장 시각, 저장 실패 상태 추가

4. 즐겨찾기
   - 사용자가 자주 쓰는 운영 메뉴를 저장
   - 헤더/사이드 메뉴와 같은 라우트 정보를 재사용
   - 빈 상태는 현재 UI 유지

5. 보유 권한
   - 현재 문자열 목록에서 권한 이름, 설명, 카테고리 기반 표시로 확장
   - 권한 수가 많을 경우 카테고리별 그룹핑 또는 검색 필터 추가

## 레이아웃 기준

- 프로필 이미지: 우측 사이드바에서 `h-40 w-40`
- 좌측 본문 영역: 남은 폭 전체 사용
- 우측 사이드바: 데스크톱 `20rem`, 태블릿/모바일에서는 본문 아래 배치
- 카드 반경: 기존 관리 화면과 맞춰 `rounded-lg`
- 카드 내부 행 높이: 최소 `44px` 수준으로 유지해 정보가 빽빽해 보이지 않게 한다.

## 백엔드 반영 시 예상 필드

```ts
type User = {
  id: number;
  email: string;
  username: string;
  profileImageUrl?: string | null;
  role: RoleSummary;
  permissions: string[];
  createdAt?: string;
};
```
